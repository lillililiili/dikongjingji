## 附录　账号切换和设置回归

设置页现在按当前登录主体管理手机号、密码状态、地址数量、注销条件和通知偏好。切换账号并返回设置时会清除上一账号的显示与弹窗，新账号可以立即读取自己的设置。保存开关采用每个账号独立的队列；写入失败时恢复服务端最近一次确认的值。同一登录主体续期后继续使用已有资料和待处理操作。注销申请和撤回之前取得的旧条件也按版本丢弃。

| 用例 | 在独立 H5、真实 API 和数据库上的操作 |
| --- | --- |
| SET-001 | 通过开发短信注册两个临时账号。将甲置于注销冷静期并修改通知开关，控制甲的注销条件读取和写入回执延迟。切为乙并返回缓存设置页，先核对甲的号码和「处理中」已清除，再核对乙的开关和注销条件可用。释放旧回执后核对乙的设置。结束时撤回甲的测试申请。 |
| SET-002 | 让账号资料请求延迟返回，经真实刷新接口取得新的访问令牌并替换当前令牌，检查原请求仍能显示当前账号的手机号与注销条件。 |
| SET-003 | 保持真实偏好读取，将同一开关快速点击两次，两次写入均由测试拦截返回 503。检查保存失败提示、页面开关以及从 API 重新读取的服务端值一致。 |
| SET-004 | 甲申请注销，延迟返回服务端已经处理成功的回执。切到乙并打开乙自己的注销弹窗，释放甲的回执，检查乙的页面仍可申请，且服务端无注销申请。 |
| SET-005 | 对同一账号延迟一次申请前取得的注销条件，成功提交注销后返回设置页，要求重新读取服务端已申请状态。释放旧条件后仍显示「处理中」。 |
