# 运营操作手册（Web 运营端与机构工作台）

> 建立：2026-11-23（计划 `docs/redesign/08-后续开发计划.md` S6 文档部分）。
> 依据：分支 `codex/app-prototype-impl` 提交 `e36e4a63`：菜单登记 `apps/admin/src/modules.ts`、各功能块 `apps/admin/src/features/*/*-module.ts`、`apps/admin/README.md`，接口 `contracts/openapi-ops-*.yaml` 及各业务契约的 `/provider/…`、`/platform/…` 部分。
> 适用：平台运营、平台客服，以及商家、服务商、活动主办、场馆运营、直播主办机构的操作员。

## 1. 登录与通用规则

### 1.1 入口与账号

- 运营端和机构工作台是同一个 Web 应用 `apps/admin`（开发地址 `http://127.0.0.1:17430`，生产由 Nginx 托管 `dist/`，`/api` 同源转发到后端）。
- 用身份模块的账号登录，**按角色出菜单**：

| 角色 | 谁 | 看到的菜单分组 |
| --- | --- | --- |
| 平台运营 `PLATFORM_OPERATOR` | 平台运营人员 | 运营（PLATFORM）：城市开通、机构与资质、商品与供给、商家资料审核、收款账户、对账下载、批量导入、发现内容、活动与场次、课程、场馆与设备、直播间、巡检服务目录、专业服务目录、服务商资料审核、系统通知；客服（SUPPORT）：客服会话 |
| 平台客服 `PLATFORM_SUPPORT` | 平台客服人员 | 客服（SUPPORT）：订单查询、用户查询、客服会话、举报与反馈 |
| 机构操作员 `PROVIDER_OPERATOR` | 商家、服务商、活动主办、场馆运营机构的员工 | 工作台（WORKBENCH）：商城订单、售后、商城询价、租赁询价、租赁订单、需求报价、服务订单、巡检预约、活动结果、客服会话、服务商资料、商家资料、收款账户 |
| 直播主办 `LIVE_HOST` | 平台开通了直播的机构的员工 | 工作台：直播间 |

- 客户账号（`CUSTOMER`）登录运营端会被拒绝。商家和服务商在身份模块里是同一个角色，菜单相同；每个页面的数据都由后端按令牌里的机构过滤（没有卖货的服务商看到的商城订单是空的）。
- 登录令牌 15 分钟过期，运营端**不续期**，过期后任何操作都会回到登录页（记住原页面）；令牌只放内存和 sessionStorage。
- 机构账号由平台运营在“机构与资质”里建，初始口令只显示一次，由运营转告机构；改角色后旧令牌立即失效，要重新登录。

### 1.2 所有写操作的共同约定

| 约定 | 说明 |
| --- | --- |
| 留痕 | 运营端每个写操作成功后提示“操作人和时间已记录”，并告诉你去哪看。记录在各模块自己的改动记录表里，**只追加不改**，详情页下方“改动记录 / 操作记录”可查（机构详情、城市各看最近 50 条）。工作台的业务操作由各模块自己记操作人（交易状态流转、租赁交接记录等），不另提示。 |
| 上线前必填 | 活动上线、场馆上线、内容上线、商品上架、课程上架、巡检和专业服务上架时，后端校验必填项；缺了回 `OPS_PUBLISH_INCOMPLETE`（商品是 `OPS_PRODUCT_INCOMPLETE`），页面显示“上线前还差：……”，按钮禁用。补齐再点。 |
| 版本冲突 | 编辑页带着读到的 `version` 提交。别人先改了会回 `OPS_VERSION_CONFLICT`（工作台是 HTTP 412 / 409），页面提示刷新：**先刷新、看清别人改了什么，再重新改**，不要用旧页面覆盖。 |
| 幂等 | 新建机构、新建商品等带幂等键：网络超时后再点一次不会重复建；同一个键内容不同会被拒绝。 |
| 金额 | 页面按元填，接口按分提交（整数）；导入表直接填分。 |
| 图片和视频 | 先经“素材上传”（JPEG / PNG / WebP ≤5 MB，MP4 ≤50 MB，按文件头判断）拿到受控 https 地址再填进表单；业务表单只收 https 地址。只用有使用权的素材（`docs/ops/授权图片替换.md`）。开发环境素材存本机目录，地址打不开，页面带登录预览。 |
| 草稿先行 | 新建的活动、场馆、内容、商品、课程、服务一律是草稿 / 未上架 / 停用，核对完再上线。上线后公开构建还要对应的发布开关打开，App 才看得到（`docs/ops/发布开关.md`）。 |
| 时间 | 一律北京时间。 |
| 个人信息 | 运营端不收、不显示客户手机号和证件号；名单只给姓、凭证只给尾号。 |

### 1.3 首页“经营概览”

平台运营、平台客服登录后，首页先是“经营概览”（接口 `GET /api/v1/ops/dashboard`，契约 `contracts/openapi-ops-dashboard.yaml`），下面才是常用功能入口；机构账号的首页只有功能入口。

- 右上角选“近 7 天 / 近 30 天 / 近 90 天”，按北京时间自然日算到今天；带箭头的“较上期”是和紧挨着的前一段同样天数比。“刷新”重新取数，数字不缓存。
- 橙色横条是平台累计净成交（累计实付减已退）。第一排是统计期内的净成交额、付款订单、付款客户、客单价；第二排是注册客户、新增客户、活跃客户（统计期内用过 App）、入驻机构（资质已审核数、本期新增）、能收款的商家（商城在售商家数）。
- “每日趋势”一次看一条线（净成交额、付款订单、新增客户三选一），鼠标移上去看当天三项数字。“下单转化”是统计期内提交的订单里完成付款、没有全额退款的比例。“成交来源”“城市分布”按净成交额排序，城市只列前 8。
- “平台资源”是当前在架数量（专业服务不算“示例”）；“到场与预约”是统计期内的核销人次、活动报名、到馆预约、巡检预约。
- “待处理”是当前还没处理的数；有数而且你有权限的那一项可以点进对应页面（例如“退款异常的订单”进订单查询并筛好状态）。
- 每项的口径写在契约说明里。看板只有汇总数，不显示任何人的资料。
- 演示数据和测试账号不计入：登录名、机构编码在排除名单里的客户、机构，以及买卖任一方在名单里的订单、报名和预约都不算；“待处理”和开通城市照常全算。名单由运维在服务端配置（《配置与权限说明》里的 `PLATFORM_OPS_STATS_EXCLUDED_*`），要加减测试账号找运维；所以概览的数可能比“订单查询”里查到的少。
- 本机开发库没有多少付款订单时，看板会很空。要演示时可以灌一份演示经营数据（`infra/dev/dashboard-demo/README.md`），演示数据都带“演示”标记，用完一条命令清掉；**只能用在本机开发库**。

## 2. 平台运营菜单

### 2.1 城市开通（`/cities`）

- 谁能用：平台运营。契约 `openapi-ops-city.yaml`。
- 操作：按名称 / 状态查城市 → 改开通状态（**已开通 OPEN / 筹备中 PREPARING / 未开通 CLOSED**），写说明 → 保存；看每个城市的改动记录。
- App 效果：城市面板只列“已开通”“筹备中”两组；筹备中的城市只能先浏览全国商品与线上体验；未开通的只能搜索到。
- 注意：状态没变会提示 `OPS_CITY_STATUS_UNCHANGED`；带版本号。开一个新城市的完整步骤见 `城市开通模板.md`。

### 2.2 机构与资质（`/organizations`）

- 谁能用：平台运营。契约 `openapi-ops-organization.yaml`。
- 操作：
  1. 机构列表（待审核在前），按名称 / 类型 / 资质状态筛。
  2. 新建机构：类型（**经营机构 PROVIDER**：商家、服务商、活动主办、场馆运营都是这类；**企业客户 CUSTOMER**）、名称（1–60 字）、所在城市。
  3. 录入资质文字：营业执照主体名称、统一社会信用代码（只校验格式）、经营范围、行业资质说明。
  4. 上传资质附件（PDF / JPEG / PNG ≤10 MB，每家最多 10 份）；下载、移除。
  5. 审核：**通过**（至少一份附件，写审核时间，App 显示“资质已审核”）或**驳回**（写原因 1–200 字）。
  6. 给机构建账号（登录名 4–32 位小写字母开头），初始 12 位口令只显示一次。
  7. 改机构账号的角色：经营机构可授“服务商操作员”“直播主办”；企业客户可授“客户”。平台角色不能在这里授。
  8. **开通服务商资料**（契约 1.1.0，S6-01）：经营机构的详情里有“服务商资料”页签，资质审核通过后点“开通服务商资料”。开通后这家机构在 App 上有服务商主页，专业服务和巡检服务详情显示服务商，需求发布时能被邀请报价；机构操作员能在工作台“服务商资料”提交主页资料（经营主体、服务方式、可交付清单等），再由平台在“服务商资料审核”（§2.14）里审。重复点不会重复开通；企业客户没有这一项。
- 注意：资料或附件有任何改动，资质自动回到“待审核”、“资质已审核”先撤下，审核通过后再出现（已开通的服务商资料不收回）。每一步都记操作记录（开通服务商资料记为“开通服务商资料”）。
- **审核通过前不可见**（2026-11-24）：经营机构新建或自助入驻后、资料待审核或被驳回时，它的商品、巡检和专业服务、活动、场馆、课程都不能上架（上线），平台代上架也会被拒；已上架的在 App 上先不可见，不能再下单、预约、报名，审核通过后自动恢复，不用重新上架。已成交的订单、预约和核销照常。没有录过资质的老机构不受影响；批量导入的机构按导入表里有没有资质审核日期。改资料前想清楚：改一个字也会先下线。
- 线下要先核对营业执照和行业资质原件。做服务的机构（不只是卖货的商家）记得开通服务商资料，否则上架的专业服务在 App 上没有服务商行、主页打不开。

### 2.3 商品与供给（`/catalog/products`）

- 谁能用：平台运营。契约 `openapi-ops-catalog.yaml`、`openapi-ops-merchant-profile.yaml`（交易条款）。
- 操作：
  1. 新建商品：类目、名称、交易方式（购买 / 租赁 / 询价，建好后不能改），先是草稿。
  2. 基本资料：一句话介绍、体验标识、排序、卖点标签（≤5 个，每个 ≤12 字）、参数、包装清单、封面、图集（≤9）、图文介绍（≤30 段），整份保存。
  3. 规格：≤20 个，新建、改名、启用停用。
  4. 在售供给：商家 × 规格 × 城市（可不填表示全国）× 价格 × 库存（空表示不限）× 配送（快递运费、自提点）。新建的供给是停用的；询价不标价，租赁按天或半天；不能快递的要有自提点；**没登记收款账户的商家标红**。
  5. 交易条款页签：七天无理由开关（默认支持）；每个供给填开票方、售后责任方（留空按商家资料，再没有就是商家名称）。
  6. 上架 / 下架。
- 注意：上架前页面列出缺什么并禁用按钮；已下的订单用下单时的快照，改条款不影响旧订单。库存这一版不在下单时扣减。

### 2.4 商家资料审核（`/merchant-profiles`）

- 谁能用：平台运营。契约 `openapi-ops-merchant-profile.yaml`。
- 操作：按状态（待审核 / 已通过 / 已驳回 / 已被替换）和关键词查 → 详情对照“这一版”和“现在对外的”（改动项标出），看机构资质审核过没有、最近 20 次提交 → 通过（整份成为 App 商家主页上的资料）或驳回（原因 ≤200 字）。
- 注意：已处理过的单再审会提示 `OPS_MERCHANT_PROFILE_REVIEW_CLOSED`；商家待审核时再交一版，上一版作废。

### 2.5 收款账户（`/merchant-accounts`）

- 谁能用：平台运营。契约 `openapi-ops-catalog.yaml`（merchant-accounts）。
- 操作：按“是否登记”筛经营机构 → 登记或修改微信二级商户号（8–32 位数字）和收款开关 → 看每家的登记记录。
- 注意：**只登记，不做进件**；进件在微信服务商后台完成后再填。占位号段 `1900000xxx` 只有开发环境能登记。没登记或关着收款的商家：商品照常展示，但买家不能提交订单；活动、场馆、课程、租赁、服务订单同理不能收费。

### 2.6 批量导入（`/imports`）

- 谁能用：平台运营。契约 `openapi-ops-import.yaml`；填表规则 `docs/ops/首批资源导入.md`；模板 `infra/import-templates/`（31 个 CSV，只有表头）。
- 操作：选一类 → 上传这一类的几张 CSV → **预检**（逐行问题表；统一社会信用代码等不进库的核对列单独列出，拿去和线下材料对照）→ 全部通过后**导入**（一个事务，失败不留半截）→ 看新建 / 更新了哪些对象；新操作员账号的一次性初始口令只弹出这一次。
- 能导入的：经营主体与操作员、收款账户、商品与供给。**活动、场馆、巡检和专业服务、发现内容这一版只能预检**，要用对应菜单手工录入。
- 注意：同一批次或同样内容的文件再传不会重复写；同一编号第二次导入是更新。导入文件存私有存储 180 天（到期清理的定时任务还没做）。导入后都是草稿或停用，逐条核对后再上架。

### 2.7 活动与场次（`/activities`）

- 谁能用：平台运营。契约 `openapi-ops-activity.yaml`。
- 操作：新建草稿 → 改活动（类型、主办 / 承办机构、城市、地点、年龄、收费方式与单价、**允许候补、允许团队报名**、封面与图集、参与条件、名额说明、退改说明、报名须知）→ 场次新增 / 修改（北京时间）→ **上线**（缺必填时列出）→ 需要时下线、停售 / 恢复售卖场次。
- 候补和团队报名（契约 1.1.0 起）：两个开关在“活动信息”里，新建默认关，只有免费、按人收费的活动能打开（询价活动不能在线报名，开关是灰的）。
  - 允许候补：场次满员后 App 上能排候补（一条 1–10 人），有名额放回来时按排队顺序转正，转正后 15 分钟内确认（免费）或付款（收费）。
  - 允许团队报名：领队在 App 上代报 2–20 人（人数上下限固定），一张团队报名单、一人一码；名额不够时不能候补。
  - 随时可以关，已有报名、候补也能关：关掉候补后满员的场次显示“已满”、不能再排队，**已在排队、已转正的候补照常按顺序转正、确认或付款**（页面显示还有几条在排队，保存前会提示）；关掉团队报名后不能再团队报名，已有的团队报名照常按人取消、退款、改期、核销。开关的变化写进改动记录。
  - 批量导入的活动两个开关都是关，导入后在这里打开。
- 注意：上线过的活动不能删，只能下线；从没上线过的草稿可以删；有过报名单的场次不能删。收费活动的主办机构要先登记收款账户（没登记时 App 上报名、候补、团队报名都付不了款）。给场次加名额不会自动让候补转正（等下一次有名额放回）。

### 2.8 课程（`/courses`）

- 谁能用：平台运营。契约 `openapi-ops-course.yaml`；说明 `docs/redesign/09-课程实现说明.md`。
- 操作：新建草稿（先选线上课或线下班，建好不能改；开课机构从机构列表搜，线下班选挂靠的活动）→ 线上课资料（副标题、封面与图集、价格〔留空为不单独出售〕、有效期、适合年龄、讲师、课程包含、参数、图文介绍、试听入口、附带于哪些商城商品）→ 目录（章 ≤20、每章课时 ≤30、全课 ≤200；时长；试听；视频上传 MP4 或粘贴 https）→ 上架 / 下架。
- 注意：有人学过的课时不能删；开课机构要登记收款账户；课程视频要有授权。

### 2.9 场馆与设备（`/venues`）

- 谁能用：平台运营。契约 `openapi-ops-venue.yaml`。
- 操作：场馆草稿（运营机构、城市、封面、地址、电话、营业时间、检票与迟到规则、信息条目、项目摘要、排序）→ 项目（时长、价格、年龄、每场人数）启用 / 停用 → **按周模板批量生成场次**（一次 ≤200 场，已有的和已过的跳过）→ 停售 / 恢复 / 取消场次 → 馆内设备及关联商品 → 上线 / 下线。
- 注意：上线前要有封面、营业时间、启用的项目、未来在售场次；**有预约的场次只能停售，不能取消**。收费项目的场馆运营机构要登记收款账户。

### 2.10 发现内容（`/content`）

- 谁能用：平台运营。契约 `openapi-ops-content.yaml`、`openapi-ops-media.yaml`。
- 操作：图文（案例、知识）、视频、专题三个标签页 → 新建草稿 → 编辑正文块（段落、小标题、要点表、步骤、条目、提示、文末说明、正文配图）、“内容中提到”（类型 + 稳定 ID）；视频填封面、播放地址、时长、横竖屏、话题、运营排序；专题填起止日期、挂的活动 / 场馆 / 图文和商家内容 → 上线（立即或定时）/ 下线。
- 注意：商家发布的内容在 App 标“广告”；视频要有城市；视频和直播在资质与备案办好前只在预览构建显示。

### 2.11 直播间（`/live`）

- 谁能用：平台运营。契约 `openapi-ops-live.yaml`。
- 操作：看全部机构的直播间（标题 / 主办机构 / 状态）→ **强制结束**（写原因）→ 给已结束的直播设或去掉回看链接 → “主办机构”页签看开通了直播的机构，“开通直播主办”给机构账号加 `LIVE_HOST`（调机构与资质的改角色接口，记在机构操作记录里）；收回在机构详情里改角色。
- 注意：直播服务商未定，生产配置 `LIVE_STREAM_PROVIDER=none` 时直播间建不了。

### 2.12 巡检服务目录（`/inspection-services`）

- 谁能用：平台运营。契约 `openapi-ops-inspection-catalog.yaml`。
- 操作：
  - 服务：新建（先未上架）→ 修改（服务商、标题、简介、类目、封面、计价方式与起步价、单位、价格说明、取消说明、可预约状态、主按钮、巡检方式、含报告、覆盖城市、服务项目、价格因素、能力、流程、交付物、保障）→ 上架 / 下架。
  - 类目：新建（编码定了不改）、改名称 / 副标题 / 排序、启用 / 停用。
- 注意：下面有上架服务的类目不能停用；App 只显示上架、资料齐全、覆盖当前城市的服务。

### 2.13 专业服务目录（`/pro-services`）

- 谁能用：平台运营。契约 `openapi-ops-proservice.yaml` 1.1.0。
- 操作：航拍、测绘、设备维护、技术支持服务的新建、修改（服务商、类型、场景分类、标题、简介、封面、排序、起步价或按项目报价、质保期、上架城市、筛选项、卡片标签、能力、价格与取消、服务内容、成果格式、服务方式、说明行、流程、保障）→ 上架 / 下架。
- 注意：上架前要有城市、筛选项和服务流程。

### 2.14 服务商资料审核（`/provider-profiles`）

- 谁能用：平台运营。契约 `openapi-ops-proservice.yaml`（provider-profiles）。
- 操作：列表（待审核在前）→ 详情并排对比“App 上正在显示的”和“待审核的” → 通过 / 驳回（原因 ≤200 字）。
- 注意：驳回后主页仍显示上一份通过的。只有在“机构与资质”里开通了服务商资料的机构（§2.2 第 8 步）能在工作台提交，这里才会有它。

### 2.15 系统通知（`/system-notices`）

- 谁能用：平台运营。契约 `openapi-notification.yaml` 1.5.0 起的运营部分。
- 操作：发布公告：发给全体或某个城市、标题、列表摘要、正文（空行分段）、≤4 个要点、≤6 条“主要变化”、文末说明、主按钮、关于哪份协议、有效期 → 发布；需要时**撤回**（从所有人的“消息”里拿掉）。
- 注意：**发布后不能改**，只能撤回再发；带幂等键防重复。推送服务商未定，非开发环境只记站内信、不推送。

## 3. 平台客服菜单

“客服”分组里的订单查询、用户查询平台运营也能看到；举报与反馈只给平台客服。

### 3.1 订单查询（`/lookup/orders`）

- 谁能用：平台客服、平台运营。契约 `openapi-ops-lookup.yaml`。
- 操作：输入买家手机号、订单号、微信支付商户订单号、微信交易号、退款单号或售后单号（都是精确查）→ 可再按来源、状态、下单日期筛 → 点订单号看详情：金额、内容、收货城市和物流、微信支付记录、退款记录、售后、状态变化。
- 注意：**只能看**，不能改单、退款或关单（退款由商家在工作台做）。买家手机号、收货人打码，不显示详细地址和取货码。覆盖七种交易来源（商城、租赁、活动报名、到馆预约、巡检付款、专业服务、课程）；巡检预约本身、免费报名这类没有付款环节的不在这里。每打开一张订单详情记一条查看记录（查看人、时间、哪张单）。

### 3.2 用户查询（`/lookup/users`）

- 谁能用：平台客服、平台运营。
- 操作：输入手机号、账号 ID 或登录名（精确查），或显示名里的字（模糊查）→ 点显示名看详情：状态（含注销冷静期）、角色、所属机构、企业组织、近 30 天登录的设备数、交易订单数 → “查看订单”跳到订单查询，只列这个人的订单。
- 注意：**只能看**，不能改资料、停用或解锁账号。手机号打码。每打开一个用户详情记一条查看记录。

### 3.3 举报与反馈（`/feedback`）

- 谁能用：平台客服（平台运营看不到）。契约 `openapi-ops-feedback.yaml`。
- 操作：待处理 / 已处理 / 全部，按来源筛（用户反馈、举报视频评论、举报直播弹幕）→ 需要时**隐藏**被举报的评论或弹幕 → 写处理说明，标为已处理。
- 注意：每条只能处理一次；平台只协助沟通、不裁决；对外不承诺处理时限。

## 4. 机构工作台菜单（商家 / 服务商 / 主办 / 场馆）

都只看、只改**本机构**的数据（机构只从令牌里取，别的机构的单当作不存在）。写操作先确认；改状态的操作带 If-Match，别人先改了会提示刷新。

| 菜单 | 谁 | 怎么操作 | 注意 |
| --- | --- | --- | --- |
| 商城订单 `/workbench/mall-orders` | 商家 | 按 待发货 / 待自提 / 已发货 / 退款中 / 全部 查 → 详情 → **发货**（物流公司、运单号）、**自提核销**（6 位取货码）、**退款**（可部分，按元填） | 取货码连续输错 10 次锁定该单；退款不超过实付 − 已退 − 正在退；退款经平台支付渠道原路退回 |

### 4.1 活动和场馆的核销

核销**不在 Web**：主办 / 场馆机构的操作员用 App“我的 → 工作模式”扫码或输码（见 `用户操作手册.md` §14）。核销员就是机构的操作员账号，运营在“机构与资质”里给机构建账号即可；没有单独的核销员名单页。
