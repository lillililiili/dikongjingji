# 数据库结构及初始化说明

> 建立：2026-11-23（计划 `docs/redesign/08-后续开发计划.md` S6 文档部分）。
> 依据：分支 `codex/app-prototype-impl` 提交 `e36e4a63` 的 `backend/modules/*/migrations/`、`backend/bootstrap/src/main/resources/db/development/`、`ModuleFlywayFactory.java`、`ModuleFlywayConfiguration.java`。
> 表结构以迁移文件为准；本文是索引，字段细节看迁移和对应契约。

## 1. 数据库与迁移机制

- 数据库：PostgreSQL 16 + PostGIS（生产镜像 `postgis/postgis:16-3.5`）；坐标用 WGS84（SRID 4326）。金额一律整数分；敏感资料（联系人、地址等）在应用层加密存储（`INSPECTION_DATA_ENCRYPTION_BASE64_KEY`）。
- 迁移：Flyway，**每个模块一套**，迁移文件在 `backend/modules/<模块>/migrations/`，打包到 `classpath:db/migration/<模块>`，历史表 `flyway_history_<模块>`。Spring 自带的 Flyway 关闭，由 `ModuleFlywayConfiguration` 在后端启动时跑：先身份、再巡检（建平台城市目录和 PostGIS），其余模块（活动、体验、站内信、需求、专业服务、租赁、服务订单、客服、内容、收藏、直播、课程、账户、交易、导入、商城）排在它们之后，依赖关系见各 Bean 的 `@DependsOn`。
- 规则：迁移只加不改（已发布的迁移不再修改，改动另起新版本号）；模块之间不建跨模块外键，只存对方的稳定 ID。
- 初始化时，启动后端会自动执行各模块迁移。正式环境的初始内容包含全国省市目录（340 条城市记录）、身份角色与权限、两种趣玩挑战的关卡定义。首个平台运营账号的创建步骤见 `配置与权限说明.md` §1.3。商品、场馆、活动等经营资源通过运营端录入或批量导入（`docs/ops/首批资源导入.md`）。开发示例资源由单独的 dev 迁移加载。
- 全局搜索模块 `search` 没有自己的表（经端口读各模块）。
- 备份、恢复：`infra/prod/backup/pg-backup.sh`、`pg-restore.sh`，见 `docs/ops/部署与回滚.md` §5、§6。

## 3. 开发种子（只在开发环境）

- 日常维护库使用默认配置 `PLATFORM_DEMO_DATA_ENABLED=false`。启动时执行正式结构迁移并保留已有业务记录及历史迁移表。全新维护库通过 `PLATFORM_BOOTSTRAP_OPERATOR_LOGIN` 与 `PLATFORM_BOOTSTRAP_OPERATOR_PASSWORD` 首次创建运营账号。
- 独立演示或测试库可在 `dev` 配置下显式设置 `PLATFORM_DEMO_DATA_ENABLED=true`。此时加载 `backend/bootstrap/src/main/resources/db/development/<模块>/` 的脚本，沿用历史表 `flyway_history_<模块>_development`。运行前核对 JDBC 指向独立数据库，使用独立 Redis、测试 API 地址和可写媒体目录。Compose 部署使用不同项目名、端口及数据库卷。
- 开发种子写入示例机构、商品、活动、场馆、服务、内容、直播、课程、城市轮播和地图地点。用户随后注册、下单，商家上架以及运营编辑产生的记录同样保存在数据库。各模块按业务字段区分示例，部分表没有逐行的数据来源字段。
- App 与 Web 通过后端读取业务记录。图片和视频在数据库中存引用，实际文件由媒体服务或对象存储提供。开发记录可引用 `/api/v1/dev-media/…`。从仓库根目录运行开发后端时默认读取 `apps/mobile/src/static`，从其他目录或容器运行时通过 `DEV_MEDIA_ROOT` 指向相应媒体目录。没有媒体引用的记录显示缺图或暂无视频。
- 开发库中的示例商户号用于模拟支付。微信支付、短信、直播等外部服务按环境配置选择适配器。设备定位、用户当前输入、最近搜索及未登录时的本机仿真结果属于设备产生的状态。已登录用户的业务记录以各接口读回的结果为准。
- 平台协议只有发布且已到发布日期、具有正文的版本才供 App 读取。尚无正式内容时接口返回 404。趣玩挑战的两套内置关卡随数据库迁移初始化，目录与棋盘由接口提供，玩家移动和计时在设备上计算。
- 开发账号：`identity/R__dev_identity_accounts.sql`（dev-customer、dev-provider、dev-merchant、dev-merchant-2、dev-organizer、dev-support 等，口令写在种子里，不进任何文档）；开发运营账号 `identity-operator/R__dev_identity_operator.sql`，只在设了 `DEV_OPERATOR_PASSWORD` 时建。
- 演示模式下，活动、体验、内容和直播的样例在首次启动或演示日期变化后按北京时间重排。独立演示库若需在持续运行时每日更新，另设 `PLATFORM_DEMO_DATA_REFRESH_AT_MIDNIGHT=true`。自动化测试通常保留默认的 false，测试开始前初始化当日数据。
- 依赖顺序：内容种子提到活动、场馆，排在它们之后；交易种子（收款账户、商家操作员）排在身份、商城等种子之后（见 `ModuleFlywayConfiguration` 的 `@DependsOn`）。
- 已有库切换为日常维护模式时保留业务 ID、历史订单、关联和操作记录。已知示例按核实结果逐批维护。演示模式仅用于允许反复重载的专用数据库。

## 4. 敏感数据与对象归属

- 收货地址、预约联系人和地址、参与人姓名和出生年月、团队领队手机：只给所属账号读写，所有查询以 `owner_id` / `account_id` 为条件；日志不记。
- 核销记录只存凭证号尾 4 位；持有人只给姓。
- 交付文件、资质附件、售后凭证只经受权接口或短时链接读，不给存储地址。
- 运营改动记录、机构操作记录、收款账户登记记录、状态迁移记录都只追加。
