# 后台逐页与 App 联调验收

2026-11-26 对运营、客服和机构工作台开展验收。后台按注册路由盘点，共 35 个业务模块、39 个去重菜单入口、75 条业务路由。登录、商家入驻、首页、无权限页和未找到页另计，共 80 条。表中同一页面的页签和弹窗归入所属模块。

首轮验收基于本地 `main` 的 `c0f9dadd` 加工作区改动。下文的首轮统计和跨日证据对应这一版本。此后合入远程 `082c587c` 的 25 个提交，合并后的变更和复验单独记录。

## 测试环境

Windows、Chrome、真实 Web 后台和 uni-app H5、JDK 21、PostgreSQL、Redis、MinIO。隔离库为 `inspection_e2e_admin_20261126`，从空库执行项目迁移，覆盖后台 `17438`、API `18428`、H5 `5185` 和开发支付适配器 `17468`。真实测试使用独立开发账号，临时故障和过期版本用例用来核对失败与恢复行为。浏览器分别用运营、客服和机构账号点击 22、4、16 个菜单，合计 42 次，去除 3 个共享入口即 39 个。另有 8 个新建或次级表单、12 个直接以现有数据打开的详情页、16 个在跨端业务流程中进入的详情页，以及 5 个通用路由。

## 本轮修复

| 操作 | 原来会发生什么 | 修复和回归 |
| --- | --- | --- |
| 编辑已有资源 | 部分详情请求失败时仍可提交，可能将已有资源当成新增。加载较慢时还可能覆盖操作者刚输入的标题 | 编辑器区分新建和编辑，读失败可重试，载入和保存期间禁用输入。对图文、视频、专题、活动和场馆复现后实测，巡检和专业服务额外验证上架后的标题。 |
| 运营发布与留痕 | 未保存的输入可能在上下架时丢失。读取审计记录失败时容易被理解为从未修改。快速切换可能串出另一条记录 | 在发布前提示保存或放弃。详情与历史记录可分别重试，只显示当前资源的结果。验证商品、城市、场馆、直播和服务目录。 |
| 需求报价与租赁 | 调整价格会重置原本约好的有效期 | 表单回填已存截止时间，提交后与数据库、买家侧报价及合同核对。 |
| 巡检履约 | 发布修订前缺少服务商读取现行方案的接口，需要重新填写金额、日期和条款。交付弹窗需要自行判断应上传的文件类型 | 增加按服务商所属预约鉴权的读取接口。修订沿用当前版本，交付按已确认方案列出所需类型。用一份 PDF 走完上传、交付、验收及尾款。 |
| 商家工作台 | 详情刷新失败时仍可能按旧状态操作；直播预告、讲解清单和回看分区保存相互影响 | 数据重新取得后再开放相关操作，直播分区保留各自输入。验证当前版本冲突、改价、改分和客户侧结果。 |
| 客服查询与处理 | 按用户查单后旧筛选残留。打开详情再返回会丢失客户刚查的条件和页码。11 位数字登录名与手机号重合时可能漏查。举报处理状态在刷新后丢失 | 返回列表恢复查询条件、页码和每页条数，从菜单重新查则开始新查询。按用户和状态跳转时使用新入口的条件。恢复状态限当前导航，搜索词不写入地址栏或浏览器持久存储。修正数字账号查询和脱敏。举报原文可核对，评论及弹幕处理状态经后台刷新及 App 复验。 |
| 导入、收款和对账 | 换文件后仍可执行旧预检，多条同名文件的历史记录容易点错。收款记录接口失败时可能显示空记录，无交易且无应对账商户的历史日期无法导出 | 换文件使旧预检失效，模板可直接下载。结果和历史均按服务端的批次号打开详情。两次连续实测核对批次号、导入机构编码和历史详情，详情请求失败后可重试。收款记录也可重试；空账期可下载表头，确有应对账商户时仍须取得账单。已验证补导、重复导入、强制重导。 |
| 经营概览 | 从近 7 天切到近 90 天时断网，页面已选 90 天却保留了 7 天的金额 | 切换统计期立即清除上一期数据。失败后可重试，浏览器按同一次响应核对 7、30、90 天的金额、退款、净额、客单价、趋势、待办和刷新结果。六类待办均为零时核对空态。随后从 App 新增反馈和咨询，客服从首页的两条待办分别进入处理和回复，客户侧确认回信。 |
| 新账号首次登录与机构改角色 | PostgreSQL 和应用分别判断授予时间，约 6 毫秒的时差就可能让首次登录成功的客户没有参与人权限 | 用数据库语句时间统一判断立即授予、撤回及有效区间，机构权限同时核对归属。针对应用比数据库快和慢 5.581 毫秒各签发令牌三次，分别核对首登、撤权和恢复，以及未来、过期角色。运营查询和首页客户统计使用相同的角色有效范围。 |
| 公共操作 | 会话资料请求短暂失败会退出登录。删除或筛选到空页后分页状态可能错误。菜单搜索键盘操作不完整 | 资料恢复后可回到原页，令牌失效时重新登录。修复分页和键盘选项，浏览器复验快捷搜索、换页签、刷新和权限页，在 1024 与 1280 像素宽度检查主页面水平溢出。 |
| App 首页 | 轮播首次请求失败时缺少反馈，返回首页可能仍显示已下架内容 | 独立反馈和重试，回到首页或切换城市重新读取，忽略过期响应。按数据库核对排序、上架、下架和图片访问。 |

## 复验方法

在工作目录使用 `E2E_PG_DATABASE` 指定以 `inspection_e2e_` 开头的专用 PostgreSQL 库。运行 `node infra/dev/e2e/stack.mjs up` 启动测试 API、后台与开发支付适配器；本机还需先按仓库说明准备 JDK 21 的隔离 JAR 及容器镜像。在另一终端用相同库名运行 `node infra/dev/e2e/stack.mjs test <spec>`。下列套件中运营数据和协议的写入用例分别需要 `E2E_OPS_CONTENT_TEST=1`、`E2E_OPS_AGREEMENTS_TEST=1`。测试栈注入独立凭据，H5 连接同一测试 API。

| 浏览器范围 | 复验文件，均在 `apps/mobile/e2e` 下 |
| --- | --- |
| 全部菜单、页签、新增表单、已有资料详情、会话恢复、地图地点维护 | `admin-navigation-audit.spec.ts` |
| 内容、课程、通知、城市、巡检与专业服务、场馆设备和场次 | `ops-editor-integrity.spec.ts`、`ops-page-content.spec.ts`、`ops-published-cover.spec.ts`、`ops-play-games.spec.ts`、`ops-agreements.spec.ts`、`admin-course-simulation.spec.ts`、`content-ops-figures.spec.ts` |
| 管理台经营概览、权限、商品订单和售后 | `admin-workbench.spec.ts`、`admin-dashboard-interactions.spec.ts`、`aftersale.spec.ts` 中 ASL-001 至 ASL-004 |
| 商家入驻、资料审核、商家和服务商的工作台与 App 履约 | `merchant-signup.spec.ts`、`merchant-quote-revision.spec.ts`、`ops-organization-accounts.spec.ts` |
| 查单查人、反馈、客服、导入、账务 | `admin-support-operations.spec.ts`、`admin-lookup-filters.spec.ts`、`support.spec.ts` 中 SUP-001 |
| 直播及举报、地图网络异常、消息和协议链接 | `ops-live-moderation.spec.ts`、`destination-map.spec.ts`、`system-notice.spec.ts` |
