```sh

node infra/scripts/s6-rehearsal/01-resources.cjs
node infra/scripts/s6-rehearsal/02-goods.cjs
node infra/scripts/s6-rehearsal/03-service.cjs
node infra/scripts/s6-rehearsal/04-activity.cjs
node infra/scripts/s6-rehearsal/05-city.cjs
node infra/scripts/s6-rehearsal/06-consistency.cjs
node infra/scripts/s6-rehearsal/07-recovery.cjs replay
node infra/scripts/s6-rehearsal/07-recovery.cjs prepare-restart   # 然后重启后端（带 IDENTITY_ACCOUNT_JOBS_CLOSURE_INTERVAL_MS=5000）
node infra/scripts/s6-rehearsal/07-recovery.cjs verify-restart
node infra/scripts/s6-rehearsal/07-recovery.cjs identity          # 然后按原方式重启后端
node infra/scripts/s6-rehearsal/07-backup-restore.cjs
```

- 全部经真实 HTTP 接口操作；`docker exec homerev-postgres-1 psql` 只用于准备（两处缺口的绕过、把时间挪到过去触发定时任务）、只读核对和清理。
- 每一步写一行到 `.runtime/s6-rehearsal/<脚本>-<时间>.jsonl`（请求、预期、实际、是否通过），终端打印 `ok / FAIL / KNOWN`；`KNOWN` 是已登记的缺陷（不算失败，单独计数）。
- 清理：脚本记下自己建的对象 ID 和自己登录的会话 ID，结束时（失败也会，`try/finally` 的写法）从这些 ID 出发做闭包清理——先只读收齐所有引用它们的行，再反复删到删不动；只删 `created_at` 不早于脚本开始时间的行，碰不到种子和别人的数据。然后按同一个 ID 集合把所有表查一遍（含 jsonb 列）要求残留为 0，再把每张表的行数和脚本开始时比，不能多出行。本机存储里路径含这些 ID 的文件一起删。`lib.cjs` 开头有说明。
