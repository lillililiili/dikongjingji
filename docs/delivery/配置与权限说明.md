## 1. 账号、机构与角色

### 1.1 机构类型（`identity_organization.organization_type`）

| 类型 | 含义 |
| --- | --- |
| `CUSTOMER` | 企业客户 |
| `PROVIDER` | 经营机构：商家、巡检和专业服务商、活动主办 / 承办、场馆运营都是这类 |
| `PLATFORM` | 平台机构（运营端不管理它） |

### 1.2 角色（`identity_role`）

| 角色 | 名称 | 作用范围 | 来源 | 能做什么 |
| --- | --- | --- | --- | --- |
| `CUSTOMER` | 客户 | 全局 | 身份 V001 | App 客户侧全部写操作：预约、确认方案、验收、下单、报名、收藏、评论、会话、反馈等；只看自己的数据 |
| `PROVIDER_OPERATOR` | 服务商操作员（商家、服务商、主办、场馆共用） | 限定机构 | 身份 V001 | 机构工作台：巡检出方案与履约、商城发货 / 核销 / 退款 / 售后、询价报价、租赁报价与交接、需求报价、服务订单、活动结果、客服回复、商家 / 服务商资料、App 工作模式核销；只看本机构的数据 |
| `PLATFORM_OPERATOR` | 平台运营 | 全局 | 身份 V001 | 运营端全部平台菜单（除“举报与反馈”）；跨租户读巡检预约、方案、服务单、交付下载和审计；对账、支付通道自检、收款账户登记；发系统通知 |
| `PLATFORM_SUPPORT` | 平台客服 | 全局 | 身份 V004 | 回复“平台客服”会话；运营端“举报与反馈”；隐藏任意视频评论、直播弹幕，强制结束直播。**不带任何巡检权限，也拿不到平台运营的权限** |
| `LIVE_HOST` | 直播主办 | 限定机构 | 身份 V006 | 建直播间、改预告、讲解清单、回看链接、隐藏本机构直播间的弹幕；不带巡检权限 |
| `SYSTEM` | 系统任务 | 全局 | 身份 V001 | 服务端定时任务内部使用，不给人登录 |

巡检模块另有细粒度权限（`identity_permission`，身份 V001、V003），按角色授：

| 角色 | 巡检权限 |
| --- | --- |
| CUSTOMER | `inspection.reservation.create`、`.reservation.read.own`、`.reservation.cancel.own`（V003）、`.plan.read.own`、`.plan.confirm.own`、`.order.read.own`、`.delivery.download.own`、`.acceptance.create.own` |
| PROVIDER_OPERATOR | `inspection.reservation.read.assigned`、`.plan.publish.assigned`、`.order.read.assigned`、`.order.arrange.assigned`、`.order.progress.assigned`、`.delivery.publish.assigned` |
| PLATFORM_OPERATOR | `inspection.reservation.read.all`、`.plan.read.all`、`.order.read.all`、`.delivery.download.all`、`.audit.read` |

### 1.3 谁来授角色

| 角色 | 怎么授 |
| --- | --- |
| PROVIDER_OPERATOR、LIVE_HOST（经营机构）、CUSTOMER（企业客户） | 平台运营在运营端“机构与资质”给机构建账号、改角色（`PUT /api/v1/ops/organizations/{id}/accounts/{accountId}/roles`）；批量导入 `01b-organization-operators.csv` 也能建操作员 |
| PLATFORM_OPERATOR、PLATFORM_SUPPORT | 运营端**不能**授。生产由运维按 `docs/ops/微信支付联调清单.md` 第 2 步用 SQL 给已有账号加；仓库里没有生产用的建号工具（待定） |
| 开发环境 | 开发种子 `R__dev_identity_accounts.sql`（dev-customer、dev-provider、dev-merchant、dev-merchant-2、dev-organizer、dev-support 等，口令见种子文件，不写进文档）；dev-operator 只在设了 `DEV_OPERATOR_PASSWORD` 时建 |

角色有改动时账号的令牌版本加一，旧令牌立即失效。**个人客户没有自助注册**（S5-8 手机号登录未合入）。

### 1.4 登录令牌

- `POST /api/v1/auth/login` 用户名密码登录，返回访问令牌（JWT，HMAC 签名，**900 秒**）和刷新令牌。
- `POST /api/v1/auth/refresh` 换新访问令牌和新刷新令牌（轮换）；已换掉的刷新令牌再用视为被盗，整串撤销（身份 V008）。
- `POST /api/v1/auth/logout` 撤销这次登录。App 会自动续期；运营端不续期，15 分钟后重新登录。
- 账号和机构**只从令牌里取**：所有“本人 / 本机构”的数据都按令牌过滤，别人的对象一律当作不存在（404）。

## 2. 接口前缀与权限

| `POST /api/v1/live/stream-callbacks` | 不登录，**验签** | 直播服务商回调 |

| `/api/v1/provider/**` | `PROVIDER_OPERATOR` + 令牌里有机构 | 只看本机构；服务商资料接口还要求机构有服务商资料 |
| `/api/v1/checkin-workbench/**` | `PROVIDER_OPERATOR` + 机构 | 机构主办 / 承办过活动或运营场馆才有可核销种类；记录只给操作员本人 |
| `POST /api/v1/activity-checkins`、`/venue-checkins` | `PROVIDER_OPERATOR` + 机构 | 只能核销本机构的活动 / 场馆 |
| `/api/v1/live-host/**` | `LIVE_HOST` + 机构 | 只管本机构直播间 |
| `/api/v1/platform/trade/**` | `PLATFORM_OPERATOR` | 收款账户登记、对账查询与重跑、支付通道自检 |
| `/api/v1/platform/support/**` | `PLATFORM_SUPPORT` | 只到“平台客服”那一方的会话 |
| `/api/v1/platform/live/**` | `PLATFORM_SUPPORT` | 隐藏任意弹幕、强制结束直播 |
| `POST /api/v1/content/comments/{id}/hide` | `PLATFORM_SUPPORT`，或发布这条视频的机构的 `PROVIDER_OPERATOR` | |
| `/api/v1/dev/**` | 只在 `dev` 配置下注册 | 模拟直播开播事件、查看模拟推送等 |
| 其余全部（客户侧 `/inspection/reservations…`、`/trade/…`、`/mall/cart…`、`/mall/inquiries…`、`/activity-*`、`/venue-bookings…`、`/rental-*`、`/demands…`、`/service-orders…`、`/conversations…`、`/feedback`、`/favorites…`、`/notifications…`、`/account/addresses…`、`/course-enrollments…`、`/experience/records…` 等） | 登录；客户接口要 `CUSTOMER` | 只看本人；巡检按 §1.2 的权限码 |

运营端菜单与角色的对应见 `运营操作手册.md` §1.1；菜单和路由的角色登记在 `apps/admin/src/features/*/*-module.ts`，`module.test.ts` 检查两者一致。

## 3. 后端配置（环境变量）

### 3.1 基础

| 变量 | 默认 | 说明 |

| `SPRING_PROFILES_ACTIVE` | — | 开发 `dev`（加载开发种子和本机模拟）；生产 compose 用 `prod` |

### 4.2 发布开关（`apps/mobile/src/app-shell/release/release-features.json`）

编译期常量，公开构建只开 `publicRelease: true` 的项；**现在全部为 false，公开构建只有巡检**。开关列表：`ACTIVITY`、`EXPERIENCE`、`MALL`、`CART`、`TRADE`、`RENTAL`、`DEMAND`、`SERVICE_ORDER`、`PROSERVICE`、`CONTENT`、`LIVE`、`SUPPORT`、`COURSE`、`SETTINGS`、`SYSTEM_NOTICE`、`SEARCH`、`PLACES`、`FAVORITE`、`PLAY`。每个开关控制什么、打开前要满足什么、怎么打开（改 JSON + 公开版 E2E 期望 + `npm run -s verify:public-production-preview`）见 `docs/ops/发布开关.md`。App“工作模式”跟随 `ACTIVITY` 或 `EXPERIENCE`。

公开构建会删除 `static/images/preview`、`static/videos/preview`（原型示例素材无授权），`verify-public-production-preview.mjs` 检查。

## 6. 密钥管理规则

- JWT 密钥、数据加密密钥、数据库 / Redis / MinIO 口令、微信支付私钥、APIv3 密钥、微信支付公钥：只放服务器密钥配置（`prod.env`、`/etc/low-altitude/secrets/`），不进代码、仓库、客户端包和聊天。
- 天气 Key 只放服务端，不进 App。
- 开发运营账号口令只从 `DEV_OPERATOR_PASSWORD` 来；机构账号的初始口令只在建号结果里显示一次，服务端只存摘要。
- 日志不记令牌、精确坐标、手机号或完整请求体（AGENTS.md §14）。
