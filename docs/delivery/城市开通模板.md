# 城市开通模板

> 建立：2026-11-23（计划 `docs/redesign/08-后续开发计划.md` S6；建设方案 §11.1“城市复制：以配置开通第二城市，加载指定资源；跨城市和跨商家越权用例全部拦截”）。
> 依据：分支 `codex/app-prototype-impl` 提交 `e36e4a63` 的运营端菜单与契约（`contracts/openapi-ops-*.yaml`、`openapi-platform-city.yaml` 1.1.0）。
> 用法：每开一个城市复制一份本文的“检查表”（§3），逐项填“负责人 / 完成日期 / 证据”，全部打勾后再把城市改成“已开通”。

## 0. 先知道的几件事

1. **城市是数据，不是开关。** 平台城市目录（巡检迁移 V007 + `R__platform_city_reference.sql`）已经有全国省和地级市；开一个城市 = 在运营端把它的状态改成“已开通”，再把这个城市的资源上架。城市一律用编码（如东营 `370500`），不用城市名。
2. **发布开关是全国的。** `release-features.json` 的开关打开后所有城市都出现对应入口；某个城市没有资源时 App 显示空状态。所以新城市不需要改开关，但第一次打开某个功能时要按 `docs/ops/发布开关.md` §2 满足前置条件。
3. **三种开通状态**（运营端“城市开通”）：
   - `PREPARING` 筹备中：城市面板列在“筹备中”，用户可以先浏览全国商品与线上体验；适合资源还在录入时。
   - `OPEN` 已开通：列在“已开通”，正式运营。
   - `CLOSED` 未开通：面板不列，只能搜索到。
4. **全国可见的资源**：商城供给的城市留空表示全国在售；线上录播课不分城市；知识类图文可以不分城市。这些不用为新城市重录。
5. **按城市的资源**：本地供给（城市编码）、活动、场馆及场次、巡检服务的覆盖城市、专业服务的上架城市、案例图文和视频、专题、系统通知（可发给某个城市）。

## 1. 开通步骤

| 步 | 做什么 | 在哪 | 完成标志 |
| --- | --- | --- | --- |
| 1 | 把城市改为**筹备中**，写说明（例如“第二城市测试空间，2026-12 起录入资源”） | 运营端“城市开通” | 改动记录里有这一条 |
| 2 | **机构入驻**：本城的商家、服务商、活动主办、场馆运营机构逐家建档（类型选“经营机构”，所在城市选本城）；企业客户按需建 | 运营端“机构与资质”，或“批量导入”的 `01-organizations.csv` | 机构列表里能查到 |
| 3 | **资质审核**：录资质文字、上传营业执照和行业资质附件，线下核对原件后“审核通过” | 运营端“机构与资质” | App 上该机构显示“资质已审核” |
| 4 | **机构账号**：给每家机构建操作员账号、授角色（服务商操作员；要开直播的加直播主办）；初始口令当面或受控渠道转交 | 运营端“机构与资质”，或 `01b-organization-operators.csv` | 机构能登录工作台 |
| 5 | **收款账户**：机构在微信服务商后台完成二级商户进件后，登记子商户号、打开收款 | 运营端“收款账户”，或 `02-merchant-payment-accounts.csv` | 商家工作台“收款账户”显示可用；用其中一家跑一次支付通道自检 |
| 6 | **商家资料 / 服务商资料**：机构在工作台提交，平台审核通过 | 工作台“商家资料”“服务商资料”；运营端“商家资料审核”“服务商资料审核” | App 商家主页 / 服务商主页显示审核通过的资料 |
| 7 | **商品与供给**：本城的在售供给（商家 × 规格 × 本城编码 × 价格 × 库存 × 配送），交易条款（开票方、售后责任方） | 运营端“商品与供给”，或 `03-*.csv` | 供给已启用；商品已上架 |
| 8 | **巡检和专业服务**：给已有服务加本城覆盖（巡检要带距离排序用的中心点），或为本城服务商新建服务 | 运营端“巡检服务目录”“专业服务目录”（导入这一版只能预检） | 切到本城后目录能看到 |
| 9 | **活动与场次**：本城活动（主办 / 承办机构、地点、收费方式、报名须知）和场次 | 运营端“活动与场次”（导入只能预检） | 活动已上线，场次在售 |
| 10 | **场馆与设备**：本城场馆、项目、按周模板生成场次、馆内设备 | 运营端“场馆与设备”（导入只能预检） | 场馆已上线，未来 7 天有在售场次 |
| 11 | **发现内容**：本城案例、视频、专题；需要时发一条只给本城的系统通知 | 运营端“发现内容”“系统通知” | 发现页切到本城能看到 |
| 12 | **核销准备**：确认活动主办、场馆运营机构的操作员在 App“我的”里能看到“工作模式” | App | 能进核销工作台，看到本城今天的场次 |
| 13 | **按 §2 的验收用例跑一遍**，记录结果 | App、运营端 | §2 全部通过 |
| 14 | 把城市改为**已开通** | 运营端“城市开通” | App 城市面板“已开通”里有本城 |

图片一律用有使用权的（`docs/ops/授权图片替换.md`）；示例数据（开发种子）不会进生产库。

## 2. 验收用例

对应建设方案 §11.1 的“城市复制”“资源与授权”“数据一致”。用两个城市（已开通的 A、新开的 B）、两家商家（同城的甲、乙）做。

| # | 用例 | 预期 |
| --- | --- | --- |
| C1 | App 切到 B，首页、商城、赛事研学、体验、专业服务、发现各频道 | 只出现 B 的本地资源和全国资源，不出现 A 的本地资源 |
| C2 | 切到 B 后打开 A 的本地商品 / 活动 / 场馆 / 服务详情（深链） | 提示不在当前城市或不可用，不能下单 / 报名 / 预约 |
| C3 | 在 B 提交巡检预约、商城订单、活动报名、到馆预约 | 订单城市是 B；收款方是对应机构自己的子商户号 |
| C4 | 城市状态改回“筹备中” | 城市面板移到“筹备中”；改动记录多一条 |
| C5 | 商家甲的操作员登录工作台，查看、发货、退款、回复商家乙的订单或会话（改 URL 里的 ID） | 一律当作不存在，不能操作 |
| C6 | 机构操作员用工作模式核销另一家机构的活动凭证 / 到馆码 | 被拦下（非本机构），记录里不显示持有人、场次和金额 |
| C7 | 客户账号访问运营端、平台运营接口 `/api/v1/ops/…` | 401 / 403 |
| C8 | 平台客服账号访问平台运营菜单接口；平台运营访问“举报与反馈”接口 | 403 |
| C9 | 未登记收款账户的商家的标价商品 | 能看到，不能提交订单 |
| C10 | 资质被驳回或资料改动后 | App 上“资质已审核”撤下 |
| C11 | 在 B 抽 3 笔订单，对账单里能逐笔找到，金额、退款一致 | 一致 |

跨城市、跨商家越权的系统化测试和问题关闭记录由“测试报告”“问题关闭记录”另行给出（见 `交付清单.md`）。

## 4. 当前限制

- 活动、场馆、巡检和专业服务、发现内容的**批量导入只能预检**，新城市的这几类资源要在运营端逐条录入。
- 城市目录只到地级市，区县写在地址里。
- 第二城市的“测试空间”验证（计划 08 S6）还没有跑，结果由测试报告给出。
