## 修复与回归

| 问题 | 处理与验证 |
| --- | --- |
| 新手引导跳过定位后首页仍索取系统权限 | 保留手动选城偏好，首次进入直接展示选城面板。重启后从当前城市目录恢复用户选择。目录不可读取时优先使用已配置默认城市，无可用默认值则允许重试。通过 Android 重启操作、浏览器刷新及城市选择单测。 |
| 设备慢定位覆盖用户已经选中的巡检地址 | 使用延迟定位构造了可重复失败。选点页面先读取本城地点，定位完成时检查用户是否已搜索、选中地点或拖动。修复后确认地址回填正确。 |
| 演示局域网图片可见，但点开放大为空 | 图片查看器采用业务图片的地址校验逻辑，受控的本地演示媒体源也可打开。不受信任的普通 HTTP 图片仍被过滤。通过单测。 |
| 图片列表含无效地址时放大或下载错图 | 过滤后仍追踪原图索引，下载完成时记入发起请求的那张图。多图回归验证选择位置和下载回调指向同一原图。 |
| 无参数地图页缺少可操作的退出入口 | 选点和目的地空状态提供显式按钮，有历史返回上一页，独立打开返回首页。H5 深链接回归覆盖两页；Android 验证有上页的入口。 |
| 拒绝相机后原生扫码缺少替代路径 | 已授权设备自动打开系统扫码。其他设备可手动开启相机，或直接输入平台链接及码。识别继续使用原解析规则，外部地址保持拦截。原生与 H5 的受控权限用例均已验证。 |

## 可重复的检查

从项目根目录设置 `E2E_PG_DATABASE=inspection_e2e_merge_20261126` 后运行：

```text
node infra/dev/e2e/stack.mjs test "destination-map|pickers|city-sheet|catalog-route-city|service-route-city" --workers=1
```

## 环境恢复

退出隔离用户时，雷电的 Android 系统进程在停止临时用户期间异常退出。重新启动该模拟器后已确认临时用户被移除、机主 App 恢复前台，原 App 资源文件 SHA-256 与验收前一致，设备上仍有原登录凭据。只检查了凭据是否存在。机主原有的 `18420` 映射已恢复，临时调试和 QA 端口映射已移除，核对结果见本机 `restored.json`。
