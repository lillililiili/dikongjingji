# 电力巡检目录销量排序与“我的”页头部精简设计

## 目标

本次仅完成以下三项用户已确认的调整：

1. 删除“我的”页顶部的城市、天气、搜索框和消息图标整行，头像资料区上移；客服和设置保留。
2. 将巡检目录的“距离最近”改为“销量”，并明确、实现可核对的综合排序规则。
3. 将开发环境中的电力巡检商品补齐为输电线路、变电站、配电网、电缆和光伏五类，用不同价格和完成服务次数展示排序差异。

支付、预约、详情、履约及其他无关流程不在本次范围。发现无关问题只记录，不修改。

## 页面设计

### “我的”页

- 移除页面顶部整行公共头部，不再渲染城市、天气、搜索和消息入口。
- 头像、用户名称、身份状态、客服和设置所在的资料区保留，并自然上移到状态栏安全区之后。
- 不调整资料区已有样式修复，也不修改其他页面对公共头部的使用。

### 巡检目录

- 排序栏依次保留“综合排序”“销量”“价格”“城市”。
- “销量”选中时使用与现有排序项一致的激活样式。
- 删除仅供距离排序使用的定位请求、坐标状态和失败回退文案；城市自动定位及城市切换能力继续保留。
- 商品卡片展示真实完成服务次数，文案为“已服务 X 次”，作为销量排序的可见依据。

## 排序规则

### 综合排序

采用透明、固定的业务展示顺序：

1. 分类顺序：输电线路、变电站、配电网、电缆、光伏。
2. 同一分类内按 `completed_count` 降序。
3. 仍相同时按服务 ID 升序，保证分页和重复请求结果稳定。

### 销量排序

1. 按真实 `completed_count` 降序。
2. 相同时按服务 ID 升序。

### 价格排序

保持现有升序/降序切换；无固定起价的项目报价商品排在有价格商品之后，最终以服务 ID 保证稳定。

客户端只提交白名单排序值：`COMPREHENSIVE`、`SALES_DESC`、`PRICE_ASC`、`PRICE_DESC`。服务端只按白名单分支生成固定 SQL 排序，不拼接客户端字段。

## 数据与接口

- 目录请求明确限定电力巡检商品组，并携带排序参数。
- 列表响应补充已有数据库字段 `completed_count`，客户端映射为数值后展示。
- 电力商品组包括：
  - 输电线路无人机巡检：8,560 次，699 元/公里起。
  - 变电站智能巡检：6,230 次，899 元/次起。
  - 配电网无人机巡检：5,420 次，599 元/公里起。
  - 电缆通道巡检：7,310 次，799 元/次起。
  - 光伏电站无人机巡检：3,210 次，699 元/次起。
- 新商品复用仓库现有变电站、配电网和电缆图片，不新增外部图片依赖。
- 开发种子数据保持幂等，只进入开发环境；不生成生产 Mock。

按该数据，综合排序为“输电线路、变电站、配电网、电缆、光伏”；销量排序为“输电线路、电缆、变电站、配电网、光伏”，两种结果可在同一页面直接核对。

## 错误与兼容处理

- 服务端拒绝未知排序值，客户端对旧路由中的 `DISTANCE_ASC` 回退到综合排序。
- `completed_count` 缺失时按 0 处理，但正式开发数据必须返回真实值。
- 新增子分类只影响电力目录；公共“我要巡检”入口仍以 `POWER` 作为电力大类入口。
- 不修改公共城市状态、天气适配器、消息能力或其他页面的定位使用方。

## 验证与停止条件

风险等级按 L3 处理，因为涉及 OpenAPI、真实接口排序和开发种子数据。

执行顺序严格限制为：

1. 一轮实现。
2. 定向测试：排序模型、目录 API 映射、服务端排序白名单/SQL、开发种子数据、“我的”页结构。
3. 一轮完整差异审查，只修复本任务内阻塞问题；无关问题记为观察项。
4. 定向测试通过后只执行一次移动端构建。
5. 只执行一次 Android 真机验证，检查“我的”页头部、综合/销量/价格排序和五类商品筛选。

从实施开始计时，超过 60 分钟立即停止并汇报当前结果，不继续扩大验证范围。
