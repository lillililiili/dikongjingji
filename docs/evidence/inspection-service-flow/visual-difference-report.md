校准视口：`390 × 737` CSS 像素。

参考来源：用户提供的两份 UI 整改与 Codex 验收板 PDF。

```powershell
$env:INSPECTION_SHARP_MODULE='<已安装的 sharp 模块目录>'
node .\infra\scripts\generate-f09-visual-comparisons.cjs
```

每页均保留：

参考图统一等比置于 `390 × 737` 白色画布顶部，不进行非等比拉伸。M006 参考源比例较短，底部保留白色余量。首轮长截图按顶部裁切为同视口，原始长图同时保留，避免把溢出问题隐藏掉。

## INS-M-004 预约填写

首轮差异：

- 页面只显示到“现场资料”，补充说明和联系人不在首屏。
- 预约信息行、巡检项目卡和附件区高度偏大。
- 底栏与正文竞争垂直空间。

最终修正：

- 按参考比例压缩进度条、服务快照、表单行、项目卡、附件区和底栏。
- DOM 实测联系人卡底部 `661.19px`，固定底栏顶部 `662px`，无覆盖。
- 服务图、业务图标、补充说明、联系人两行、费用提示、协议和主按钮均在同一 `390 × 737` 视口出现。

允许差异：

- 服务封面和地址来自真实目录/预约数据，不从 PDF 截取。
- 图标使用项目既有 `uni-icons`，轮廓语义与参考一致但像素造型不完全相同。

## INS-M-005 预约提交结果

首轮差异：

- 成功区、服务信息与时间数据显示密度不稳定，旧截图为长页面。
- 服务图和流程曾被底栏切割。

最终修正：

- 最终截图严格为 `390 × 737`，成功区、预约信息、后续流程、提示和底栏完整。
- 中文地点、联系人和日期来自真实 PostgreSQL 预约；方案存在后底栏按连续状态流显示“查看服务方案”。
- 字体层级、圆角、橙/绿状态色和区块顺序与参考一致。

## INS-M-006 方案确认

首轮差异：

- 内容溢出，底栏未完整进入校准视口。
- 待确认状态错误使用绿色成功勾，提前表达业务成功。
- “申请调整”入口不可见。

最终修正：

- 未确认态改为橙色中性信息图标和“服务方案待确认/待用户确认”。
- 绿色成功语义只在真实 `CONFIRMED` 状态出现。
- 协议默认未勾选，“申请调整”、客服和“确认方案”均可见。
- 底栏、安全区和主按钮完整位于 `390 × 737` 视口。

允许差异：

- 方案号、金额、地址、巡检项目和有效期来自真实 API，不复刻 PDF 示例值。

## INS-M-007 服务安排与履约

首轮差异：

- 页面高度溢出，进度和固定底栏被切割。
- 状态卡、服务卡和安排卡密度偏大。

最终修正：

- 状态、服务摘要、团队/设备、五节点进度、提示和底栏在同一视口连续显示。
- 交付后同一固定底栏主按钮切换为“查看报告与验收”，不再被其他固定按钮遮挡。

允许差异：

- 服务封面来自真实服务快照；本期未接入未经用户确认的生成图片。

## INS-M-008 报告交付与验收

首轮差异：

- 页面超过视口，交付文件、进度和验收底栏不能同时看到。
- 待验收主状态使用 CSS 绘制图标，不符合图标来源要求。

最终修正：

- 报告状态、结果指标、问题摘要、四类文件、五节点进度和验收底栏完整显示。
- 待验收图标改为项目已有 `uni-icons` 的 `compose` 图标；已验收使用 `checkbox-filled`。
- 验收完成按钮为“验收已完成”，不暴露本期未实现的评价入口。
- 最终截图控制台错误为 0，页面高度严格为 `737px`。

允许差异：

- 杆塔数、长度、问题数、文件名、时间和地点来自真实交付 DTO。

## 图标与图片来源

| 类型 | 来源 | 处理 |
| --- | --- | --- |
| 返回、客服、复制、状态、表单、文件类型 | `@dcloudio/uni-ui` 的 `uni-icons` | 真实组件，不使用 Emoji、字符或 CSS 绘制替代 |
| 服务封面 | 正式目录 DTO；无封面时使用仓库既有巡检资产 | 不从 PDF 裁切 |
| 未新增的专用位图 | 无 | 本轮没有生成或接入需用户另行确认的图片 |
