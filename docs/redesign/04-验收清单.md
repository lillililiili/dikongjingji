## 0. 准备

- 预览地址：`http://127.0.0.1:17420`（开发版，能看到全部频道）。后端在 `127.0.0.1:18420`。两个都没开的话跟我说“跑起来”。
- 用应用里的浏览器面板或手机尺寸的浏览器窗口打开，宽度 375–430。
- 城市：第一次打开会问定位，拒绝或没有结果时落到东营市。清单里的内容都按东营写。
- **登录**：开发环境有三个示例账号，后端以 dev 配置启动时自动建好。账号名和密码写在 `backend/bootstrap/src/main/resources/db/development/identity/R__dev_identity_accounts.sql` 开头的注释里。验收用客户账号 `dev-customer`；`dev-provider` 是服务商操作员，`dev-organizer` 是示例场馆的签到员，这两个都没有页面，只通过脚本调接口。
- 登录 15 分钟后会过期，页面会自己跳回登录页，再登一次即可。
- **服务商一侧的动作用脚本代替**（服务商没有页面）。你在 App 里提交预约后，在终端运行下面这条，它会用 `dev-provider` 把你最近提交的那一单往前推一步，并告诉你接下来在 App 里做什么：

  ```bash
  BASE_URL=http://127.0.0.1:18420 node infra/scripts/dev-advance-reservation.cjs
  ```

  加 `--visits 3` 是发布三次巡检的方案；加 `--step` 是履约阶段一次只做一个动作，方便在履约页上逐步看；后面写订单编号可以指定哪一单。不想自己开终端的话跟我说“推进一下”。
- **活动签到用脚本代替**（主办方没有页面）。报名后把凭证页上的凭证号填进去：

  ```bash
  BASE_URL=http://127.0.0.1:18420 node infra/scripts/dev-checkin-ticket.cjs ACT-XXXX-XXXX-XXXX
  ```

  签到只能在场次的签到时间内做（开场前半小时到结束），示例场次都排在以后几天，所以平时运行会如实告诉你“不在签到时间内”。想看“已签到”的样子跟我说，我把一个示例场次临时挪到现在。
- `dev-customer` 名下已经留了四张示例订单：一张待确认（3 次巡检）、两张待验收、一张已完成（2 次巡检），可以直接点进去看。交付文件是能打开的示例文件。
- 数据全是开发示例，图片是原型里的概念图。
