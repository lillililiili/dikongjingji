## 第一批：巡检报价转预约

| 编号 | 交付与验收条件 |
| --- | --- |
| Q1 | 已选巡检报价的客户可以继续预约。重用需求中的服务商、城市、地址及报价资料，实际可订服务和时段取自服务端。缺少的信息由客户补全，提交前由本人确认协议。 |
| Q2 | 同一份需求只关联一张巡检预约。重复提交、重新打开、并发请求都不新增第二张。仅需求所属客户可转换，仅选定服务商可承接，其他机构不能查看或处理该预约。 |
| Q3 | 客户与服务商能双向核对需求、成交报价和预约。方案沿用巡检原有首付、排班、履约、报告、验收及按次付款流程。直接通过服务详情发起的预约保持原有行为。 |
| Q4 | 在隔离库从两个服务商报价开始，经真实 App、机构工作台及开发支付回执验证，检查关联唯一、金额、权限、历史数据以及直接预约回归。通过后开始第二批。 |

## 第二批：有限库存实物商品

| 编号 | 交付与验收条件 |
| --- | --- |
| S1 | 标价购买的有限库存供给在创建待付款订单时预占。App 和商家/运营工作台能核对当前可售数。未限制库存及其他交易来源按原业务规则处理。 |
| S2 | 付款成功按预占确认成交；未付款取消、超时关闭按原预占释放。重复请求和回执只影响一次，迁移前的订单按其原有库存处理方式结束。 |
| S3 | 隔离库用两个买家同时购买最后一件，验证只有一单成功。验证释放后再买、付款后无重复扣减、多商品一笔事务和跨端读回。记录实际执行结果。 |
