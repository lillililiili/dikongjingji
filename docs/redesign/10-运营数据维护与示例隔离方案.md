## 目标

运营在后台修改东营的轮播或活动后，刷新 App 就能看到新内容，第二天和服务重启后仍然如此。商家继续维护自己创建的商品。报名、订单、评价和经营指标按各自的业务记录形成。演示和自动化测试可以继续使用原型中的示例。

当前东营有 4 张轮播。地图接口返回的已发布地点中，6 个城市共有 18 个示例地点。独立线上体验有 6 项，其中 5 项已发布。趣玩有 2 个内置关卡。协议正文尚未录入。巡检服务「电力输电线路无人机巡检」的 8,560 次完成和 328 条评价均来自开发脚本。盘点口径和现有后台入口见[数据库说明](../delivery/数据库结构说明.md)及[运营操作手册](../delivery/运营操作手册.md)。

## 第一批：让日常数据能长期维护

1. **隔离日常库和演示库。** 日常 App、H5 和后台共用当前维护库。开发环境默认只执行正式结构迁移和必要的基础初始化。独立演示库显式启用示例装载，自动化测试连接自己的数据库，在每轮开始时准备约定日期的数据。开发种子在服务启动和北京时间零点都有执行路径，两处均按用途控制。首次运营账号的引导沿用现有机制。
2. **保护现有工作成果。** 切换前备份并试恢复，在副本生成只读差异清单，分别列出已知预置、带人工修改记录、已有订单或报名引用、来源待核实的记录。固定种子 ID 和现有审计记录作为依据，保留业务 ID、历史快照和操作记录。已有库先停止自动覆盖，已知样例逐批经后台下架或由运营核实并替换。来源不清的记录进入人工核对。已执行的迁移和 Flyway 历史保留。
3. **复用现有菜单。** 商品与供给、活动与场次、课程、场馆与设备、发现内容、直播和服务目录继续使用原有表单。后台优先在这些列表展示已能核实的示例标识，区分来源、是否编辑过、当前发布状态。商家只能改本机构创建的商品，历史平台商品仍由平台运营维护。
4. **补最高频的两个编辑入口。** 在平台运营端增加「首页轮播」，支持按城市新增、预览、排顺序、发布和下架，图片走现有素材上传，跳转沿用赛事研学、趣玩、体验三个现有站内目的地。在「巡检服务目录」内增设「入口配置」，维护入口横幅、场景说明、流程与已核实的保障文案，区分全局默认与城市覆盖，并在服务详情编辑器补交付样图字段。

**验收**：在后台修改一条已存在的活动及东营轮播，分别验证立即刷新、跨日持续运行、隔日重启。标题、价格、素材、排序和下架状态与最后一次保存一致；其他城市、已有报名、订单快照和评论保持正确。两名运营同时改同一条时提示版本冲突。无运营权限的账号不能调用写接口。独立演示库仍能复现原有报名、播放和下单场景。

## 与第一批并行：纠正示例业绩

- 巡检详情、目录排序和首页热门统一使用同一统计口径。建议将「已完成服务」定义为一张巡检服务单约定的全部巡检次都已验收通过，整单计 1 次。中途验收、退回整改和重复请求均不增加整单计数。交易付款及对账继续使用原有口径。
- 对现有订单先在副本按上述规则计算并与验收单对照，再切换各读取接口。正式展示的评价列表、数量和评分均排除已知示例，只计可核实且可公开的客户评价。真实数量为零时显示 0 或「暂无评价」。演示库可以呈现示例并标明来源。
- 核查开发直播的预置观众数、点赞和弹幕，以及城市预设搜索热度。真实经营页面按已有业务事件统计；缺少可信来源的数值先隐藏。后台经营概览继续查询已有业务表。如果需要客户在巡检验收后提交评价，单列「买家评价」功能，建议本人已验收订单一单一评。

**验收**：没有履约数据的服务不会因示例数字进入热门；一张包含两次巡检的订单在最后一次验收通过后只增加 1；重复提交保持原数。评价列表、评分和数量一致，运营没有手工填写成交量或用户好评的入口。

## 场馆位置、高德底图与导航应用选择

建议把场馆和活动的真实底图提前到第一批。当前场馆详情按接口提供的名称、地址和坐标调用 `uni.openLocation`。Android 工程已选择高德，H5 尚缺 Web 地图配置，iOS 尚缺对应平台的配置。「东营区示例路 66 号」来自开发库，更换底图后仍会原样显示，运营核准地址时应同时核准地图标记的位置。

2026-11-25 在本机 5182 的 Chrome 预览复现：打开东营体验馆，点击场馆导航，能读到名称和地址；运行配置中未设置高德 Web Key，控制台出现地图配置提示，高德库和地图图层均未加载。

- **浏览器和 App**：H5 优先复用当前 uni-app 已支持的高德 JS 地图，配置 Web JS Key、允许的域名和服务端安全代理。Android 核对实际运行基座或安装包的包名、签名与高德授权，iOS 按 Bundle ID 单独配置。查看场馆位置直接显示数据库坐标；用户点「定位到我」时再申请位置权限。[uni-app 地图组件](https://uniapp.dcloud.net.cn/component/map.html) · [高德 Web 安全配置](https://lbs.amap.com/api/javascript-api-v2/guide/abc/jscode)
- **业务数据**：场馆名称、地址和坐标仍在后台「场馆与设备」维护。场馆和活动共用查看位置与导航的处理，沿用入库 WGS84、进入高德时转换一次 GCJ-02 的约定。第二批的城市地点管理继续维护平台自己的候选地点；预约拖图选点另接地图适配器，第三方地点搜索可单独评估。
- **验收**：从场馆详情和活动详情进入，在 H5 和 Android 分别实测道路底图、场馆标记、缩放和导航目的地；iOS 在独立配置后的设备上验证。测试禁止定位时仍能看场馆，地图服务超时或鉴权失败时能看到地址、复制地址、点击重试。保存或调整坐标后，验证后台与 App 的标记落在同一处。

### 第一批必修：雷电模拟器场馆地图黑屏

**原始现象与修复结果**。用户在雷电模拟器打开「东营低空与机器人体验馆」的位置页时，截图只有高德标识、返回键、场馆名称、地址和导航按钮，地图区域全黑。原生日志定位到 x86 模拟器的地图引擎缺少 native 方法。地点页改用高德 Web 地图后，已在同一模拟器确认道路和目的地标记可见，并完成平移、缩放、前后台和离线恢复验证。具体构建和平台边界见[地图验收记录](../ops/场馆与活动地图.md)。

1. 在出现问题的雷电基座或安装包中，从场馆详情重走同一路径，记录首次打开和返回后重进的画面与对应时刻的 Android 日志。核对实际安装包的包名、签名、地图模块和高德鉴权结果，再检查底图请求能否成功。
2. 若鉴权和底图请求成功，检查地图视图尺寸、原生图层遮挡、前后台切换及图形渲染日志。用同一构建、同一场馆在 Android 真机对照。只有观测到渲染异常时，再对比模拟器图形模式，按证据修复。
3. 若底图加载失败或超时，结束加载状态，显示「地图加载失败」和重试入口。场馆地址、复制地址、选择导航地图始终可操作；恢复网络后可原地重试。

**验收**。必须回到雷电模拟器，在该场馆实际看到道路、地名及正确的场馆标记，平移和缩放后底图持续可见。覆盖首次打开、退出重进和切到后台再返回；拒绝定位仍可看场馆。单独验证断网后的提示和恢复重试，并保存修复前后截图及对应日志。Android 真机和 H5 的结果分别记录。

### 点「导航」由用户选择地图

点场馆或活动的地址、地图缩略图，进入站内高德地图查看位置。点详情、凭证或位置页的「导航」，直接弹出底部菜单，标题为「选择导航地图」，并显示目的地名称。场馆详情、到馆预约凭证、活动详情和报名凭证共用同一入口。即使底图加载失败，仍可从详情页选择导航。

| 使用环境 | 选择后的行为 |
| --- | --- |
| Android 和 iOS App | 支持高德地图、百度地图、腾讯地图；iOS 另提供苹果地图。优先展示能够打开的应用，选择后带入目的地进入对应地图的路线页。系统限制识别安装状态时提供网页版路线和复制地址。 |
| 手机浏览器 | 仍让用户选择地图，使用所选服务的官方路线链接。浏览器允许时可唤起 App；受限或未安装时可以查看网页版路线或复制地址。 |
| 电脑浏览器 | 选择后打开相应网页版路线。保留复制地址。 |

各地图使用后端返回的同一目的地 ID 对应的名称、坐标；按各自的坐标系和经纬度顺序生成路线。打开路线无需平台预先获取用户当前位置，起点由用户在目标地图内确认。只有地址时用地址搜索或复制，标明尚无精确定位。「取消」留在原页面。原生端优先复用符合上述体验的系统选择器，H5 的 uni-app 内置导航随底图提供方打开一条路线，需要补选项菜单。[uni-app 打开位置](https://uniapp.dcloud.net.cn/api/location/open-location.html) · [高德路径规划](https://lbs.amap.com/api/uri-api/guide/travel/route) · [百度地图调起](https://lbsyun.baidu.com/docs/webapi?title=mapadjustment%2Furi%2Fintroduction)

验收覆盖手机安装多款、仅一款和均未安装三种情况，以及电脑浏览器和限制跳转的内置浏览器。验证选择与打开的品牌一致、各地图标记落在同一场馆、取消与返回保留页面状态，并实测底图加载失败时仍能打开路线。

## 建议交付顺序

先完成副本恢复演练、种子隔离和实绩口径核对；随后交付首页轮播、巡检入口以及正式统计切换，并在具备各端高德授权配置时验证场馆、活动的底图。用「后台改一次 → H5 与雷电模拟器刷新 → 跨日并重启」验收第一批。通过后，再按地图地点、线上体验、协议、趣玩关卡依次交付第二批。每批都验证权限、发布和撤回、数据缺失提示、历史引用及现有业务回归。
