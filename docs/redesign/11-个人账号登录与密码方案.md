# 个人账号的验证码登录与密码登录

2026-11-25，用户已确认分批实施。适用于 App 和 H5 的个人客户账号。用户用一个手机号注册，之后可凭验证码或自设密码回到同一个账号。

## 现状

验证码登录会查找已绑定该手机号的用户，首次验证才创建个人客户。手机号有唯一索引，新建用户有内部登录名，但没有可用密码。密码登录接口只按登录名校验。Web 商家入驻和运营创建的机构账号有自己的用户名和角色。开发短信进入本地测试发件箱。

## 用户如何操作

| 场景 | 建议流程 |
| --- | --- |
| 第一次使用 | 默认展示“验证码登录”，注明“未注册的手机号验证后自动注册”。密码页的“注册账号”进入同一流程。验证码验证成功后，提示“可用此手机号和密码登录”，提供“设置密码”和“以后再说”。选任一项都能继续原来的预约、报名或下单。 |
| 平时登录 | 密码页支持“手机号或用户名”。个人用户填当前绑定的手机号和自设密码；原有用户名仍可登录。验证码方式始终可选。 |
| 老用户补设密码 | “我的 → 设置 → 登录密码”显示“设置密码”或“修改密码”。首次设置前验证本人当前绑定的手机号；刚在本次会话完成短信登录可直接设置。已设密码的用户修改时验证原密码。跳过设置后不反复弹窗。 |
| 忘记密码 | 从密码页进入“忘记密码”，用当前绑定的手机号收取找回专用验证码，设置新密码，再重新登录。找回流程只更新已有个人账号。 |
| 更换手机号 | 沿用原有换绑流程。换绑成功后改用新手机号配原密码登录，个人资料、订单、地址及企业身份仍归原用户。 |

## 后端与数据兼容

- 沿用现有用户 ID、手机号唯一约束、密码摘要和注册来源。设置密码只更新原账号的凭据。对老数据按实际密码状态识别能否密码登录，避免将注册来源误当作密码状态。页面只读取本人是否已设置密码。
- 注册结果以本次是否真正创建用户为准。现有代码在并发注册时先建个人机构，再处理手机号冲突。第一批需验证重复提交最终只有一个用户和一个个人机构，只有首次创建才提示设密。
- 保留原用户名接口和现有 Web 工作台。给 App 新增明确按手机号校验密码的接口，共用现有会话签发和账号状态校验。升级前只读检查是否有与手机号同形的历史登录名；如有，保留显式“使用用户名登录”的路径，避免两套标识被误认为同一账号。
- 初次设密的授权限时、一次有效，绑定用户、会话、用途和当前手机号，换号后失效。找回与登录使用独立用途的验证码。后端限制验证码及密码尝试，错误提示不透露号码是否已注册。并发设置或重放请求只能成功一次。
- 个人自助设密、改密、找回均由服务端校验账号来源、角色和状态。商家、机构操作员与平台管理账号沿用原流程。改密或找回成功时撤销旧会话，使旧访问令牌、刷新令牌和旧密码失效。密码只保存摘要，操作审计不记录密码或验证码。
- 日常库不批量改写登录名、密码或用户 ID，不按姓名、订单联系人或机构联系电话合并账号。遇到号码占用或旧数据矛盾时保留原有归属。

## 分批交付与验收

1. **第一批，打通两种登录。** 先补身份契约及服务端能力，再做注册入口、首次可选设密、设置页补设和手机号密码登录。用新用户及已有验证码用户验证两种登录返回同一用户 ID，显示相同订单、地址，跳过或完成设置均能回到发起登录的页面。验证服务重启后密码仍可用，同时回归既有用户名和商家工作台。
2. **第二批，补齐账号恢复。** 第一批通过后做改密、忘记密码、换号后的别名切换回归和旧会话撤销。验证过期码、重放、并发、错误密码、越权操作和未知手机号找回；核对历史订单及账号归属，覆盖浏览器和雷电模拟器。
3. **对外开放。** 两批联调均用独立库和服务端测试发件箱，保留当前默认公开构建的发布范围。个人注册、找回对公众开放前，接通短信服务商并用真实手机完成注册和找回验收。App 端不提供测试验证码。

## 实施结果

2026-11-25，两批均已通过验收并更新至本机开发服务。已备份现有数据，对 202 张既有业务表逐表核验。个人账号、历史订单和地址的保留情况、最终端到端结果及对外发布边界见[测试报告](../delivery/测试报告.md#个人账号登录密码)。
