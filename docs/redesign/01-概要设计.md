## 1. 重做背景与目标

### 1.1 为什么重做

现有 App 是以“我要巡检”为单一业务线的增量产品：巡检从入口到验收已打通，首页和我的围绕巡检数据工作，发现、商城只有开发预览内容（§2.1）。会议纪要与建设方案已经把产品定位升级为：

> 从“卖设备 / 卖巡检的网站”升级为“可复制的产业商业运营能力”——**资源 → 体验 → 交易 → 数据 → 城市复制**。

因此 App 不再是“巡检服务 App”，而是该商业平台面向个人与企业客户的**移动主入口**。巡检降级为“专业服务”频道中的一类服务商品。

### 1.2 App 必须支撑的四个闭环（建设方案·决策摘要）

| 闭环 | App 端要形成的结果 |
| --- | --- |
| 资源变产品 | 用户能看到“谁在卖、在哪个城市可买、怎么交付”的真实供给，而不是资源名录 |
| 流量变交易 | 内容、赛事、体验带来的用户可在 App 内完成注册、报名、购买或提交采购需求 |
| 交易变成果 | 订单关联支付回执、履约、核销、售后，用户能查到每一步的凭据 |
| 样板变复制 | 同一 App 通过“切换城市”服务多个城市，不为新城市重新发版 |

### 1.3 设计目标

1. **一个 App、多城市**：城市是一等上下文，所有目录、活动、场馆按城市授权展示。
2. **先体验、再决定**：商品与活动详情页内嵌体验入口；体验结束不自动成交。
3. **三类订单一个台账**：实物商品、服务/合同、活动报名在“我的订单”统一查询，各自保留业务状态。
4. **交易主体透明**：每个商品/服务/活动展示销售、履约主体，不因同在一个商城而混同责任。
5. **继承现有资产**：沿用现有技术栈、橙色设计语言和巡检模块代码，不推倒重写可用部分。

### 2.2 现有资产与新平台的差距

- 无统一订单、支付回执与售后能力：巡检只有自己的预约、方案和服务单，金额只到报价，代码和契约里都没有支付、退款（巡检基线 `docs/12` 明确不含）。
- 巡检服务流程是一单一次：一个预约对应一个服务单、一次交付、一次验收，验收后服务单直接 `ACCEPTED`，没有多次巡检和付款节点。用户 2026-11-04 确认多次巡检、按次验收和付款节点以 §14 D9 和画布为准，契约和状态机待修订；面积、隐患分类、交付文件等字段差异修订时逐项确认。
- M02 只覆盖电力类，搜索、筛选、翻页只在客户端处理前 50 条，未达到 AGENTS.md §19 的“调用真实 API”；目录契约里的 `/portal`、`/filters` 后端没有实现。
- 无活动/报名/参与人/核销模型；首页和发现的活动卡片只是开发预览。
- 无内容（图文、视频、专题）与推广归因；发现只有开发预览内容。
- 无场馆、体验与线索模型。
- 已有全国城市目录、共享当前城市和巡检服务的城市覆盖（`inspection_service_city`），但没有“城市空间、资源授权”概念。
- identity 已有组织、成员和角色，但 App 没有个人/企业身份切换和企业组织页面。
- 无询报价比选：一个预约同一时间只有一个有效方案（`uk_inspection_plan_current`）。

## 3. 范围与边界

### 3.1 纳入本次 App 重做

| 业务中心（建设方案 §四） | App 端承载 |
| --- | --- |
| 产业资源中心 | 商家/机构主页、可售城市、授权标识（入驻审核在后台） |
| 综合交易商城 | 设备、配件、租赁、专业服务、课程；直接购买 / 询价 / 需求发布三种交易方式 |
| 赛事、培训与研学 | 活动列表与详情、场次、参与人报名、电子凭证、退改 |
| 新媒体与内容 | 发现页图文/视频/直播预告/专题，内容挂载商品与活动 |
| 线下体验运营 | 线上体验（模拟/录播/试用）、场馆页、体验预约、到场核销 |
| 产业数据中心 | App 只负责埋点与来源标识；看板在后台 |
| 城市复制 | 城市切换、城市化目录；开城配置在后台 |

### 3.2 明确不做（App 一期）

- 空域对接、飞行审批、公安处置、反制联动、“一网统飞”（建设方案 §1.3）。
- 虚拟电厂两条产品线、多模态融合感知控制器（会议纪要第三至五章，属独立产品线，不进入本 App）。
- 原生直播推流、短视频推荐算法、复杂社区、游戏、供应链金融、区块链、用户钱包。
- 真实设备远程操控（仅在接口与授权具备时以“厂家远程演示”形式另行接入）。
- 政府采购/电子卖场通道（会议纪要 §2.4，专题论证后再定，不作为上线前提）。
- 跨商家合并支付、复杂促销叠加、预售、账期授信。

| 终端 | 用户 | 一期形态 |

## 4. 角色与核心用例

| 角色 | App 内核心用例 |
| --- | --- |
| 游客 | 选城市、浏览商品/活动/内容、线上体验（免登录可试） |
| 个人用户 | 购买、询价、报名（为本人或家人）、预约体验、售后、评价 |
| 家长（监护人） | 管理未成年参与人、代报名、确认资料使用范围 |
| 企业经办人 | 以组织身份发布需求、比较报价、确认合同订单、验收 |
| 场馆核销员 | 扫码核销体验券/报名凭证，处理异常到场 |
| 活动领队 | 查看团队名单、协助签到 |

身份规则（建设方案 §3.3）：**账户 ≠ 参与人 ≠ 采购组织**。一个账户可管理多个参与人，可加入多个组织；统一账号跨城市使用，不在每个城市重新注册。

## 5. 信息架构

### 5.1 底部导航（重做后，方案 C）

| 位置 | Tab | 定位 | 对应业务中心 |
| --- | --- | --- | --- |

规则：
- 底栏 5 个等宽 Tab，没有凸起按钮；高 60px，触控区不小于 44px（I1 文档 docs/02-screen-spec.md 的 56dp 不再适用于新底栏）。选中时图标和文字为橙色 #ff6a00，未选中为灰色；“首页”始终显示图标和文字，不换成品牌 Logo；在首页时再点“首页”，页面滚回顶部。
- 底栏只在 Tab 根页显示，二级页不放；二级页头部为返回（44×44）+ 标题或搜索框 + 右侧最多 3 个按钮。新业务进首页频道，不进底栏。
- 频道即子首页：切换频道时，搜索占位词和下方内容一起换，底栏始终停在“首页”。一期只放上表的常驻频道，不放大促、节日等临时频道。
- 城市未开通时只留全国可用的频道（如潍坊：推荐、体验、无人机、机器人、课程），占位词“搜索全国发货商品与线上体验”。
- 角标：消息显示未读数，超过 99 显示“99+”，0 或无数据不显示；购物车显示件数，0 件不显示；发现有新内容时显示红点，正在发现页时不显示，可在“我的 → 设置”关闭；首页、我的不显示角标。

与原方案差异（现有代码底栏为“首页 / 服务 / 发现 / 商城 / 我的”；2026-11-02 方案为“首页 / 商城 / 活动 / 发现 / 我的”）：
- 代码中的“服务”Tab 取消：巡检从首页“专业服务”频道进入；推荐频道的大卡“找专业服务”和金刚位“专业服务”直达该频道。
- “商城”Tab（代码与 11-02 方案都有）和 11-02 方案中的“活动”Tab 改为首页频道。“活动”与商品类目平级，不挂在商城下，保留自己的列表、详情、报名、凭证链路和“报名”订单，以此缓解与建设方案 §4.3.1“作为独立经营业务，而非商城附加页面”的冲突。
- 消息、购物车升为底栏 Tab（代码与 11-02 方案都没有这两个 Tab）。

**用户已于 2026-11-03 选定方案 C（参照淘宝底栏），取代 2026-11-02 确认的“首页 / 商城 / 活动 / 发现 / 我的”（§14 D1）。** 逐项说明见设计画布「03 导航规格 · 参照淘宝（方案 C）」：https://claude.ai/artifact/QeP6pitH3c8hG1PVRPLT7E 。

## 6. 核心业务流程

### 6.1 设备与标准服务（直接购买）

```text
发现商品 → 商品详情（可先体验）→ 选择在售商家 → 确认订单 → 支付
           └→ 加入购物车 → 购物车（按商家分组，一期每次结算一个商家）→ 确认订单 → 支付
→ 发货 / 预约 → 收货 / 验收 → 评价 → 售后与对账（后台）
```

### 6.2 非标准需求（询价 / 需求发布）

```text
提交需求 → 平台按范围分派给服务商 → 服务商报价（版本化）→ 用户比选
→ 确认服务范围与合同 → 按节点付款 → 履约 → 成果验收
```
巡检 M04–M07 即本流程的一个实例，保留其幂等约束；状态机待修订，支持多次巡检和按次验收（§2.2）。巡检的付款节点按 §14 D9：确认方案后付首付，之后每次验收后按次付款。

### 6.3 赛事与教育活动

```text
内容触达 → 活动详情 → 选场次 + 选参与人 → 支付（免费活动跳过）
→ 报名成功（电子凭证）→ 通知 → 现场扫码签到 → 活动完成 → 成果/证明 → 评价 → 关联推荐
```

### 6.4 先体验、再决定（会议纪要 §2.3）

```text
商品/活动详情 → 选择体验形式（虚拟仿真 / 录播演示 / 试用 / 线下）
→ 完成体验 → 体验结果页 → 用户自主选择：收藏 | 对比 | 再试 | 咨询 | 预约线下 | 下单
```
约束：体验结束**不**自动生成订单；虚拟仿真、录播、远程真机演示、实际试用在界面上明确区分标识。

### 6.5 线下核销

```text
用户出示凭证二维码 → 核销员扫码 → 服务端校验（场次、有效期、未核销）
→ 核销成功 / 重复核销拦截 / 异常人工核验 → 订单履约状态更新
```

### 6.6 订单状态机（建设方案 §6.1）

| 订单类型 | 主业务状态 | 完成凭据 |
| --- | --- | --- |
| 实物商品 | 待付款 → 待发货 → 已发货 → 已收货 → 已完成 | 物流/交接记录、收货确认 |
| 服务及合同 | 待报价 → 待确认 → 待履约 → 履约中 → 待验收 → 已完成（付款节点单列） | 合同范围、服务记录、验收材料 |
| 活动报名 | 待付款 → 报名成功 → 待参加 → 已签到 → 已完成（免费跳过付款） | 报名资料、签到核销记录 |

支付、退款、售后、结算各自独立状态，不用一个“已完成”代替全部业务。取消订单释放名额或资源。

## 7. 功能模块设计（App 端）

### 7.1 城市首页（APP-HOME-01）

头部两层：
- 上层是城市（点开切换）加横滑频道行（§5.1）。
- 下层是常驻搜索框：扫一扫、随频道变化的占位词、“搜索”按钮。不放拍照搜，也不放消息按钮（消息已是底栏 Tab）。

推荐频道自上而下：
1. Banner（城市运营配置）
2. 两张等宽大卡：“找专业服务”“去体验”
3. 金刚区，一行加分页：
   - 第 1 页：无人机、机器人、专业服务、设备租赁、培训课程（去向待确认，画布暂定活动频道·培训，§14 D12）
   - 第 2 页：赛事活动、研学体验、线下场馆、全部频道
4. 今天去体验（暂放，位置待确认，§14 D13）
5. 近期活动（横滑，带报名状态与名额）
6. 本地精选（双列）
7. 附近场馆
8. 城市资讯（暂放，位置待确认，§14 D13）

所有区块无数据时整体隐藏。

### 7.2 商城与商品（APP-MALL-*）

- 类目：无人机、机器人、配件、租赁、课程各是首页的一个频道，共用商品列表模板。专业服务是独立频道（§7.3）。“全部”由金刚区“全部频道”兜底。
- 商品卡按交易方式显示主按钮：**立即购买 / 联系询价 / 发布需求**；可直接购买的商品在详情页另有“加入购物车”；价格未明确显示“询价”，不显示虚拟低价。
- 商品详情突出“**同型号多商家供给**”：在售商家列表展示价格、交期、发货城市、售后条件（建设方案 §4.1.2）。
- 体验标签：支持模拟体验 / 可预约线下体验 / 支持试用。
- 企业采购入口：进入需求发布（企业身份）。
- 数字课程（设计假设，§14 D15）：支付成功后自动开通，不发货、不走物流，在“我的 → 我的课程”学习。

### 7.3 专业服务（APP-SVC-*）

入口是首页“专业服务”频道，默认“巡检”；推荐频道的大卡“找专业服务”和金刚位“专业服务”直达该频道。复用巡检模块：M01 结构推广为“专业服务频道”（巡检、航拍、测绘、设备维护、技术支持），M02/M03 原样复用。需求发布与报价比选为新增通用页，巡检预约作为其模板之一。

### 7.4 活动（APP-ACT-*）

- 入口：首页“活动”频道，活动列表是频道根页；与商品类目平级，不挂在商城下。
- 活动类型共用基础能力，分别保留报名、排课或核销要求。
- 报名：账号与参与人分离，支持家长代报、团队批量报名、候补与满额提示、重复报名校验。
- 未成年参与人：监护人确认，照片与公开素材单独授权。
- 凭证：二维码 + 场次 + 地点 + 状态；活动延期/取消时推送并提供改期或退款。

### 7.5 体验与场馆（APP-EXP-*）

- 线上体验类型：虚拟仿真（H5/WebGL 小任务）、录播演示、软件试用（隔离环境）、课程试听。
- 体验记录归档在“我的 → 体验记录”，可再次进入。
- 场馆页：开放时间、可预约项目与场次容量、展示设备清单、到馆导航。

### 7.6 发现（APP-CNT-*）

频道：推荐、视频、赛事、研学、案例、知识。内容卡底部挂“关联商品/活动”卡，点击进入对应详情并携带内容来源标识。直播仅做预告与外部回看入口，不自建推流。

### 7.7 我的（APP-ME-*）

账户卡（个人/企业身份切换）→ 订单五态（待付款、待发货/待履约、待参加、待验收、售后）→ 最近一笔进行中业务卡 → 我的参与（报名、体验预约、体验记录、我的课程）→ 参与人、企业组织、收藏对比、客服、设置 → 工作模式入口（仅授权角色可见）。

### 7.8 核销工作台（APP-STAFF-01）

授权核销员可见：今日场次与已核销/应到人数、扫码核销、手动输入凭证号、异常登记。核销接口在服务端校验场馆与场次归属，不只隐藏入口。


## 9. 核心数据对象（概要）

| 对象 | 关键字段 / 关系 |
| --- | --- |
| Account 账户 | 登录身份；1:N Participant；N:M Organization |
| Participant 参与人 | 姓名、证件类型（按活动需要）、是否未成年、监护人账户 |
| Organization 组织 | 企业资料、成员与角色 |
| City 城市空间 | `city_code`、开通状态、品牌配置 |
| Merchant 经营主体 | 商家/机构/场馆/服务商；资质、合作状态 |
| Authorization 资源授权 | 主体 × 城市 × 品类 × 有效期 |
| Product / SKU | 型号；Offer（商家供给）= 商家 × SKU × 城市 × 价格/交期/售后 |
| Activity / Session | 活动与场次；容量、价格、退改规则版本 |
| Experience | 体验形式（仿真/录播/试用/线下）、关联商品或活动、结果记录 |
| Venue | 场馆档案、可预约项目、场次 |
| Content | 图文/视频/专题；关联商品、活动；推广标识 |
| Order | 类型、商品快照、经营主体、经营城市、履约城市、来源；1:N 履约/核销/售后 |
| PaymentReceipt | 渠道回执、金额、幂等键 |
| Verification 核销 | 凭证、场次、核销员、时间、结果 |
| AfterSale | 退款/退货/改期，回连原订单 |

原则：金额用最小货币单位 `long`；订单保留商品、规则、分配版本快照；城市用 `city_code`；所有对象带审计字段与乐观锁。

## 10. 权限、安全与合规

- 服务端按“账户 × 组织 × 城市 × 经营主体”做数据范围校验，不依赖隐藏菜单。
- 参与人、联系方式、地址、合同为敏感数据，最小范围展示；导出留痕。
- 未成年人信息需监护人确认；活动照片公开使用需单独授权。
- 支付、隐私告知、平台交易协议在正式运营前专项确认，App 按确认结果配置。
- 演示数据与生产数据隔离；测试账号不得计入经营数据。
