## 1. 规则（服务端已按此实现）

### 1.1 候补

1. 只有**满员且活动允许候补**的场次（`ActivityEnrollmentStatus.FULL_WAITLIST`）能排队；一条候补 1–10 人，人数不超过场次总名额；同一个人同一场只能在一条还在排队或已转正的候补里，也不能和已报名重复。团队报名不支持候补。
2. 候补期间不收费，随时可以放弃。
3. **转正顺序**：一场有名额放回来（取消凭证、待付款订单关闭、改期离开、候补放弃或超时）时，在同一个事务里从排在最前的候补开始，**人数放得下的依次转正**——同单几个人一起转正；最前面那一单放不下时它继续排在最前，后面人数放得下的先转正（画板“同单 2 人一起转正，余位不足 2 个时继续排队”）。这是设计假设 S53-1。
4. 转正时名额就为它占住（计入场次已报名数），**保留 15 分钟，且不晚于场次开始**，同时发一条站内信“候补转正”（活动提醒，跳候补详情）。
5. 保留时间内：**免费**的“确认报名”，提交即报名成功；**收费**的“去付款”，这时才建报名单和交易订单（钱进主办机构的子商户号），付款截止就是保留截止，付款后报名成功。
6. 没在保留时间内确认的，定时任务（每分钟，`activity.waitlist.expire-delay-ms`）把它作废、名额给下一位；收费的去付款后没付，交易模块超时关单，名额照样放回、给下一位。候补读成“已超时”。
7. 场次开始时还在排队的候补结束（“候补未成功”）。
8. 运营给场次加名额时不会自动转正（没有放回名额的事件），等下一次有名额放回时一起转；这是已知限制。
9. 新报名能拿到“排在最前的放不下”剩下的零散名额（这时场次读成“报名中”）。

### 1.2 团队报名

1. 领队代报 **2–20 人**，一张团队报名单（`kind = TEAM`），一人一码。
2. 名单：可以选领队名下已有的子女，也可以现填**姓名 + 出生年月**；现填的记成领队名下的“队员”（`MEMBER`），不出现在“参与人”页，下次团队报名直接用；和领队名下同名同出生年月的子女或队员算同一个人。提交前“核对名单”逐行给出年龄是否符合、是否已报过这一场、名单里是否重复，不符合的不计人数和费用，页面上可以移除。
3. 团队名称、领队姓名、**领队手机**（11 位）必填；领队手机只给领队本人看，页面打码（`138****2026`），主办方工作台不显示（设计假设 S53-2，见 §4）。
4. 勾选“已取得全部队员监护人的同意”和报名须知才能提交。
5. 收费活动领队一次付清（同个人报名：15 分钟、经 M14）；之后按人取消、按人原路退款。名额不够回“名额不够”，不能候补。

### 1.3 改期

1. 场次开始前，把**整张报名单**还没用的凭证改到**同一活动**另一个可报名（报名中、名额够）的场次；这些人在那一场没有另报，按新场次当天算年龄仍符合。有人已签到、待付款、已取消的不能改。（画板可以只改其中一人；按整单改是设计假设 S53-3。）
2. **立即生效**，不用主办方确认（和到馆预约的改期一样，见 03 计划 §21.1 第 5 条）：原凭证作废（不再列在报名单上），新场次一人一码重新发放，名额跟着转过去，原场次放出的名额按候补顺序转正。
3. 收费的不补差、不退款（同一活动同价）；交易订单不变。
4. 报名单记最近一次改期前的场次和改期时间（订单页“原时间 / 新时间”），发一条站内信“报名已改期”。

### 1.4 退改记录与退改详情

1. 每次取消（已付款或免费的）和改期记一条退改记录：类型、申请原因（时间冲突 / 身体不适 / 行程有变 / 其他，可以不选）、人数、原场次、新场次、收费的退款单和金额。
2. 取消接口加 `reason`（补 R6 遗留）；改期接口也带 `reason`。
3. 退改详情：退款进度是**提交申请 → 退款中 → 已到账**，状态和到账时间都来自交易模块（退款单的状态和 `succeeded_at`）；不做“等待主办方确认”“撤销申请”（退款提交即退，画板里这两步按现行规则不出现）。改期详情给原场次、新场次、“无需补差价”和新凭证。

### 1.5 结果记录

1. 主办或承办机构的操作员在 Web 工作台（`apps/admin` WORKBENCH “活动结果”）给**已签到**的凭证录入：完成情况（完成 / 未完成）、成绩（≤40 字）、证书说明（≤100 字，只是文字）。可以改，改的时候带版本号。
2. 工作台只列本机构最近 180 天已经开始的场次；名单姓名只给姓（`王**`），凭证号只给后 4 位（参与人资料只对所属账号可见，AGENTS M09）。
3. 客户在凭证、订单和结果页看到；第一次录入时发一条站内信“结果已发布”（同一张报名单一条）。

## 2. 接口（契约 1.4.0）

| 接口 | 说明 |
| --- | --- |
| `POST /api/v1/activity-waitlists`（Idempotency-Key） | 加入候补 |
| `GET /api/v1/activity-waitlists?active=` | 我的候补（active=true：排队中、已转正、待付款） |
| `GET /api/v1/activity-waitlists/{id}` | 候补详情 |
| `POST /api/v1/activity-waitlists/{id}/abandon` | 放弃（已去付款的先关单） |
| `POST /api/v1/activity-waitlists/{id}/confirm` | 转正后确认报名 / 去付款 |
| `POST /api/v1/activity-team-enrollments/check` | 核对团队名单，不写数据 |
| `POST /api/v1/activity-team-enrollments`（Idempotency-Key） | 团队报名 |
| `POST /api/v1/activity-enrollments/{id}/reschedule` | 改期 |
| `GET /api/v1/activity-enrollments/{id}/changes/{changeId}` | 退改详情 |
| `POST /api/v1/activity-enrollments/{id}/cancel` | 加了 `reason` |
| `GET /api/v1/provider/activity-sessions` | 工作台：本机构已开始的场次 |
| `GET /api/v1/provider/activity-sessions/{id}/roster` | 工作台：名单和结果 |
| `PUT /api/v1/provider/activity-tickets/{id}/result` | 工作台：录入 / 修改结果 |

`Enrollment` 加 `kind`、`team`、`reschedule`、`changes`、`reschedulable`；`Ticket` 加 `result`；`ParticipantRelation` 加 `MEMBER`；错误码加 `ACT_WAITLIST_NOT_AVAILABLE`、`ACT_WAITLIST_ALREADY_JOINED`、`ACT_WAITLIST_STATE_INVALID`、`ACT_RESCHEDULE_NOT_ALLOWED`、`ACT_RESULT_NOT_ALLOWED`、`ACT_RESULT_VERSION_CONFLICT`。站内信加跳转目标 `ACTIVITY_WAITLIST` 和三个事件码 `ACTIVITY_WAITLIST_OFFERED`、`ACTIVITY_RESCHEDULED`、`ACTIVITY_RESULT_RECORDED`。

## 4. 设计假设与没做的

- **S53-1** 转正“放得下的依次转正”（§1.1 第 3 条）。
- **S53-2** 领队手机只给领队本人看；AGENTS M09 规定活动不收手机号，画板 TeamSignup 有“领队手机”，按画板收，但只用于领队自己核对，不给主办方、不进通知。主办方要联系领队走客服会话。要不要给主办方看，请用户定。
- **S53-3** 改期按整张报名单；画板 EnrollRefund 能只改其中一人（只改一人要把报名单拆开，交易订单也只有一张，先不做）。
- **S53-4** 画板 TeamSignup 的“批量导入”是下载 Excel 模板、选文件；App 里没有文件解析，改成“复制模板 + 粘贴名单”（每行“姓名 出生年月”）。
- **S53-5** 结果记录的“完赛证明 PDF 下载”不生成文件，只显示主办方写的证书说明文字。
- 画板 EnrollResult 的“活动延期”“活动取消”两帧是主办方发起的延期 / 取消，本步没有这个流程（要运营端或工作台发起、批量退款），没做。
- 画板 EnrollRefundDetail 的“等待主办方确认”“撤销申请”“改期未成功”：现行规则提交即退、改期立即生效，不出现。
- 画板 TeamSignup 的“所属单位 · 企业账号”一行：企业组织（S5-7）不在本分支，没做。
- CalendarPick 画板里另两种用法（巡检预约选日期、到馆选日期）在巡检和体验模块，本步只接了活动；日历组件可以复用。
- S4-4 的“报名参与人姓名”：主线（交易 0.6.0）已经让活动把参与人姓名带进交易订单；团队报名和候补转正走同一条路径，也带姓名。
