# 发布开关（S2-5）

> 建立：2026-11-22（计划 `docs/redesign/08-后续开发计划.md` S2-5，默认决定：公开构建保持现状只开巡检，各功能做成发布配置，上线前由你逐项打开）。
> 现状：**全部开关关着**，公开构建和改造前逐字节相同（2026-11-22 用同一台机器构建前后两次 H5 比对 `shasum`，436 个文件全同）。

## 1. 开关在哪、怎么生效

一处配置：`apps/mobile/src/app-shell/release/release-features.json`。每个功能一行，`publicRelease` 是公开构建默认开不开。

| 构建 | 规则 |
| --- | --- |
| 开发服务器（`npm run dev:h5`） | 全部打开（和以前一样） |
| 预览构建（`VITE_PLATFORM_PREVIEW_ENABLED=true`） | 全部打开，示例内容、示例图片都在（和以前一样）；`VITE_FEATURE_*=false` 在预览构建里不起作用 |
| 公开构建（`.env.production`，`VITE_PLATFORM_PREVIEW_ENABLED=false`） | 只开 `publicRelease: true` 的功能；一次性构建可以用环境变量 `VITE_FEATURE_<KEY>=true` 或 `false` 覆盖（只认这两个值，写错构建直接失败） |

实现：`vite.config.ts` 读上面的配置和环境变量，用 `define` 变成编译期常量 `__RELEASE_FEATURE_<KEY>__`（以及表示预览构建的 `__RELEASE_PREVIEW_BUILD__`）；每个模块自己的开关文件读自己的常量，例如
`export const MALL_PREVIEW_ENABLED = import.meta.env.DEV || __RELEASE_FEATURE_MALL__`。常量在每个用到它的文件里都是字面量，关着的功能在那里折叠成 `false`、代码被摇掉。页面不 import 配置文件本身（`release-flags.test.ts` 检查），这样不会再出现“共享开关被挪进公共分包、压缩器折叠不掉、示例内容漏进公开包”的老问题（见 `features/activity/application/activity-preview.ts` 的注释）。

**打开一个功能的步骤**

1. 先满足 §2 表里“打开前要满足”的每一条，有依赖的一起开（例如 `TRADE` 要和 `CART`、`MALL` 一起）。
2. 改 `release-features.json` 里那一行的 `publicRelease` 为 `true`，和对应的公开版 E2E 期望（`apps/mobile/e2e/public-build.spec.ts` 现在断言这些入口都不出现）放在同一个提交里。
3. `cd apps/mobile && npm run -s verify:public-production-preview`：先打印“这次公开构建开了哪些开关”，再构建并检查——没有开发和示例内容、没有没替换的开关常量、首页三个频道（赛事研学、体验、商城）在包里的“公开可见”和开关一致。
4. 用构建出的 `dist/build/h5` 跑公开版 E2E：`E2E_PUBLIC_BUILD=1 npx playwright test e2e/public-build.spec.ts`；App 包再按 AGENTS.md §15 L4 做真机验收。

## 3. 还跟着“预览构建”走、不随单个开关打开的东西

这些是首页上的示例或整块内容，现在只在预览构建出现。单开某个功能后它们仍不出现，要随首发一起开时另做（改 `pages/home/index.vue` 让它们读对应开关，并补公开版 E2E）：

- 首页轮播（示例活动的海报）、扫一扫按钮；
- 首页“推荐”频道下半部分的推荐聚合（读赛事研学、商城、场馆三块）；
- 首页搜索框的占位词（公开构建固定为“搜索巡检服务、场景或关键词”，搜索只进巡检目录）；
- 专业服务频道的“发布需求”条（受 `PLATFORM_PREVIEW_ENABLED` 和巡检的类型化网关控制）。

## 4. 示例图片和公开包

- 各模块的示例图（`*-preview-covers.ts`、`content-preview-videos.ts`）只认开发种子里的那几个 ID。生产库没有开发种子，所以即使打开功能，生产数据也不会显示示例图；服务端给了 `cover_url` 等字段时一律用服务端的。
- 但 `apps/mobile/src/static/images/preview/`（46 张，约 2.8 MB）和 `static/videos/preview/`（8 段，约 2.3 MB）现在会被原样拷进公开包。它们是原型里的图片，没有确认使用权。上线前要么换成有授权的图，要么在公开构建里排除这两个目录（见 `docs/ops/授权图片替换.md` §4）。这一条改了以后公开包会变，所以这次没有动。
