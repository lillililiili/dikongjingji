# 场馆与活动地图

场馆详情、预约凭证、活动详情和报名凭证共用地点页。点地址可查看位置，点“导航”可选高德、百度、腾讯地图或复制地址，iOS 另有苹果地图。App 优先列出系统能识别的已安装地图，启动失败时打开对应服务的网页路线。H5 交给地图服务的公开导航网址处理。

## 数据与坐标

名称、详细地址和经纬度取自场馆、活动或报名接口。后台统一存储 WGS84 坐标。显示高德标记或打开内地地图导航时复用项目的 GCJ-02 转换，百度链接显式声明 GCJ-02，苹果地图接收原始坐标。坐标为空或超出范围时仍可复制业务地址。浏览地址无需申请定位权限。导航起点由所选导航应用确定。

用户点“定位到我”时读取一次设备位置，地图切换到“我的位置”。“返回目的地”恢复原场馆或活动标记，导航按钮始终使用业务目的地。定位失败保留原地图和重试入口，位置只存于当前页面。

## 底图与授权

默认通过高德托管点标记页加载地图。移动设备使用嵌入页，桌面浏览器使用高德的标注 URI。App 在页面 WebView 内绘制，避开雷电 x86 基座内没有匹配高德原生引擎的问题。高德不可达或加载超时后，页面提供“重新加载”，底部保留名称、地址、地图选择和复制入口。

如部署方已开通高德 Web JS API，可在 H5 构建同时提供以下两个环境变量。详细配置见[高德安全密钥使用说明](https://lbs.amap.com/api/javascript-api-v2/guide/abc/jscode)。

| 配置 | 用途 |
| --- | --- |
| `VITE_AMAP_WEB_KEY` | 绑定发布域名的 Web 端 JS API Key |
| `VITE_AMAP_WEB_PROXY_PATH` | 同源安全代理前缀，例如 `/_AMapService`，由部署方按高德说明配置代理 |

JS 安全密钥放在代理服务端。Android SDK Key、天气 Web 服务 Key 与 Web JS Key 各自独立。配置 Web JS 后，以 SDK 完成事件确认加载；代理或授权异常时显示加载失败。托管点标记页属于外部服务，跨域限制下只能检测网页可达性，内部瓦片是否绘制需在目标设备上目视复核。高德接口详见[单点标注](https://lbs.amap.com/api/uri-api/guide/mobile-web/point)与[网页嵌入](https://lbs.amap.com/api/uri-api/guide/embedded-map/single-location)。

正式 Android 打包时合并项目的 `AndroidManifest.xml`，其中仅声明三款导航应用的包可见性。iOS 方案白名单位于 `manifest.json`。系统查询规则见 [DCloud Runtime](https://www.html5plus.org/doc/zh_cn/runtime.html) 和 [Android 原生清单配置](https://uniapp.dcloud.net.cn/tutorial/app-nativeresource-android)。

## 回归入口

在 `apps/mobile` 执行 `npm run test -- --run src/shared/map` 验证坐标、链接编码及缺坐标处理。启动开发库、后端和预览 H5 后，执行 `npm run test:e2e -- e2e/destination-map.spec.ts` 验证场馆地址、错误重试和活动的地图选择。发布前以目标设备复核已安装导航应用的唤起、未安装时的网页版路线、底图街道与目的地标记。

### 2026-11-25 雷电实测

雷电 Android 14 的运行 ABI 为 x86，已安装 HBuilder 基座仅在 ARM 目录包含高德原生引擎。旧版打开场馆地址时底图全黑，日志反复报告 `GLMapEngine.nativeMainThreadTrigger` 无对应 JNI 实现。

更新预览资源后，从场馆详情触摸地址，实际绘出道路、建筑和目的地红标。用 Android 触摸拖图后，红标横坐标从约 154 移到 6 CSS 像素。双击放大后，高德比例尺从 50 米变成 25 米。选择导航可见高德、百度、腾讯的网页版以及复制地址；关闭选择器后刷新成功。通过 CDP 仅让该页面临时离线，出现错误提示并保留业务地址和导航按钮；恢复网络后点重新加载重新绘出地图。按系统 Home 键再返回、退回场馆详情再打开，均重新确认高德画布、目的地和 50 米比例尺。测试前后设备权限一致。

雷电上的三款第三方导航应用均未安装。实点“高德地图（网页版）”后，Android 启动系统浏览器并交给高德官方导航 URI，返回后可继续查看场馆。已安装应用的原生唤起、iOS 真机，以及配置正式域名与代理后的自有 Web JS Key 分支尚未实测。本地验收截图与手势测量在 `.runtime/acceptance/amap-*.png` 和 `amap-native-lifecycle.json`。

雷电实点“定位到我”取得系统位置，成功显示“我的位置”，再点“返回目的地”恢复场馆标记，全程沿用设备原有权限。H5 浏览器自动化验证了打开地点时不取位、手动定位成功、返回场馆，以及拒绝定位后的错误提示和重试按钮。

## 运营维护预约候选地点

工作台“城市开通”右上角和平台运营导航都可进入“地图地点”。新增或编辑时选择城市，填写名称、详细地址、WGS84 经度与纬度、排序和启用状态。App 巡检预约与需求发布沿用同一地点搜索接口；带当前位置时先按距离排序，同距离或未提供位置时按运营排序和地点键排列。停用记录可以再启用。

表 `platform_map_place` 保留原始种子和已有地点。Inspection V019 增加管理 UUID、版本及追加式变更表，不替换业务地址和坐标。初始样例编辑后仍保留来源标志，列表显示“示例 · 已维护”。新建由工作台生成管理 UUID，同一提交网络重试复用该 UUID。编辑加行锁核对版本，过时的表单返回 409；写地点和保存审计在同一事务提交。审计保留操作人和每个版本修改前后的名称、归属、地址、坐标、排序、状态。移动到其他城市会产生该城市的公开候选键，管理 UUID 保持不变，历史预约继续读取提交时保存的地址与坐标。契约见 `contracts/openapi-ops-map-places.yaml`。

2026-11-25 在独立恢复库用客户 API 通过旧候选提交一张预约。随后实际从浏览器后台改名、改地址与坐标，前往 uni-app H5 巡检选点按新名搜索，看到新地址。停用后相同公开查询返回空数组，页面显示未找到。复核该预约的地址密文与地理坐标、其他城市全部地点指纹均一致。已验证未登录 401、客户读写 403、重复新建复用初始记录、过时版本 409、坐标越界 400、审计保留改动前后值。验证截图储存在本机 `.runtime/acceptance/map-places-*.png`。拖图选点沿用原项目独立适配流程。
