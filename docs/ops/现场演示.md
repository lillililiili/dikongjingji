# 现场演示

> 给招标现场演示用：一台笔记本加一台手机，不连外网。对应技术规范书第六章（二）的 8 项演示内容。
> 演示环境和日常开发环境完全分开（容器、端口 194xx、密钥、数据都是自己的），状态在 `.runtime/demo/`，不进仓库。
> 支付是模拟微信，短信是模拟短信，不产生真实扣款和短信。**只能在本机用，不能部署到服务器。**

## 1. 提前准备（有网络的地方做）

从仓库根目录运行。准备 JDK 21 并设置 `JAVA_HOME`，按根目录的 `package.json` 安装 Node、pnpm 和工作区依赖（`pnpm install --frozen-lockfile`）。首次构建需要能下载 Maven Wrapper 的分发包和 Maven 依赖。运行演示还需可用的 Docker Compose 及本机已经准备好的镜像。

```bash
node infra/demo/demo.mjs build
```

脚本复制当前后端源码及迁移到临时目录，调用仓库的 Maven Wrapper 构建，生成 `.runtime/demo/backend.jar`。随后通过本地 Node CLI 做后台类型检查、构建后台到 `.runtime/demo/admin`，构建手机浏览器版到 `.runtime/demo/h5`，并将原生 App 资源输出到 `output/demo-app`。日常工程的 Maven `target` 和前端 `dist` 可继续供开发使用。H5 通过同源代理访问后端。原生 App 优先连接构建时的局域网地址。

Windows PowerShell 可按以下方式使用已安装的 JDK。把首行改成本机 JDK 21 的实际路径。只在本机浏览器检验时设置 `DEMO_HOST=127.0.0.1`，供手机访问时改用笔记本的局域网 IPv4。

```powershell
$env:JAVA_HOME = 'C:\Java\jdk-21'
$env:DEMO_HOST = '127.0.0.1'
node infra/demo/demo.mjs build
```

如已在其他独立构建目录打出与本次源码一致的 Spring Boot 可执行 JAR，可先设置 `DEMO_BACKEND_JAR` 为其绝对路径，再执行同一个 `build`。后端步骤改为复制该文件，后台、H5 和原生资源仍会全部构建。PowerShell 可用 `Get-FileHash -Algorithm SHA256` 核对交付包与 `.runtime/demo/backend.jar`；后续需要从源码打包时，清除当前终端的 `DEMO_BACKEND_JAR`。

### 离线镜像

默认镜像及版本在 `infra/compose.yaml`。若演示机使用预装的其他 MinIO 镜像，可在 `.runtime/demo/` 保存仅用于本机的 Compose 覆盖文件，指定真实镜像名，并给 `minio-init` 配置同版本的客户端或私有桶初始化命令。在同一终端为 `up`、`down` 设置 `DEMO_COMPOSE_OVERRIDE`。本机验收使用了如下配置路径。

```powershell
$env:DEMO_COMPOSE_OVERRIDE = (Resolve-Path .runtime/demo/minio-local.override.yml).Path
```

本次覆盖文件使用本机已有的 `helmet-legacy-minio:latest` 与镜像内的 curl，按 S3 Signature V4 对 `dev-inspection-quarantine`、`dev-inspection-private` 先 HEAD，缺失时 PUT 创建，再验证签名 HEAD 返回 200、匿名 GET 返回 403。凭据由 Compose 在运行时从演示环境提供。默认 Docker 地址池已用满的机器还可在该文件中给 `inspection-internal` 指定经核查未占用的子网。演示项目名为 `low-altitude-demo`，卷由各演示服务独享。

装到手机（二选一）：

1. **数据线直接跑**：HBuilderX 打开 `output/demo-app`，“运行 → 运行到手机或模拟器”，用标准基座。基座自带扫码、相机模块，不用打包。
2. **云打包**：HBuilderX “发行 → 原生 App-云打包”，要登录 DCloud 账号，资源会上传到 DCloud。`manifest.json` 已声明扫码（Barcode）和相机模块。

手机第一次打开要同意隐私说明、选定位或城市，提前点完。给 `dev-customer`、`dev-organizer` 各登录一次更省时间（一台手机就用“设置 → 退出登录”切换）。

## 2. 当天

1. 笔记本开热点（或接一个不联网的路由器），手机连上。**关掉笔记本和手机上的代理**，代理会拦局域网地址（笔记本上看 H5 用 `http://127.0.0.1:19450` 不受影响）。macOS 弹“是否允许接入网络”要点允许。
2. 启动并准备：

```bash
node infra/demo/demo.mjs up
```

```bash
node infra/demo/demo.mjs prepare
```

`up` 复用已有演示数据，`prepare` 准备约 2 小时后开始的收费活动场次，并生成四类样例交付文件（`.runtime/demo/samples/`）。只有明确需要清空演示数据重新开始时才运行 `node infra/demo/demo.mjs reset`。

3. 运行自动彩排，验证巡检、商城、售后、活动、入驻、经营概览六项。彩排生成的订单和入驻资料会保留，便于随后在后台核查。专家指定数据与手机并排展示两项按下表现场操作。

```bash
node infra/demo/rehearse.mjs
```

只在笔记本上看、不接手机时，代理可以不关，启动时带上 `DEMO_HOST=127.0.0.1`（工作台上传交付文件走的是文件存储的局域网地址，代理开着会被拦）：

```bash
DEMO_HOST=127.0.0.1 node infra/demo/demo.mjs up
```

打开三个窗口：运营端和工作台 `http://127.0.0.1:19430`、演示控制台 `http://127.0.0.1:19440`（看短信验证码、付款和退款流水）、手机投屏。地址用 `node infra/demo/demo.mjs status` 看。

账号：客户 `dev-customer`、巡检服务商 `dev-provider`、商家 `dev-merchant`、核销员 `dev-organizer`、平台客服 `dev-support`，口令见 `apps/admin/README.md`；平台运营 `dev-operator` 的口令在 `.runtime/demo/stack.env`。

| 5 入驻审核与上架 | 网页 | 登录页“申请入驻”（验证码看控制台）→ 用新账号登录，“我的商品”建商品、上架被拦 → 平台运营审核资质 → 再上架 | 审核前机构和运营端都上不了架、App 看不到；审核后看得到；资质改动回到待审核后又看不到 | 5 分 |

第 5 项：标价商品要先登记收款账户（平台运营“收款账户”，演示环境接受 `19000009xx` 占位号），选“询价”商品就不用。新机构先在“入驻资料”上传营业执照附件，没有附件不能审核通过。

## 4. 出问题时

- 手机连不上：看代理关了没有、防火墙放行没有、`status` 里的地址和手机是不是同一网段。实在不行用手机浏览器打开 `http://<笔记本地址>:19450`（不能扫码，核销改手输码）。
- 付款后没变：控制台看这一笔是不是“已付款”；App 里点“刷新结果”。
- 某个服务没起来：`.runtime/demo/logs/`。
- 演示完：`node infra/demo/demo.mjs down` 停掉（保留数据），`reset` 清空。

## 5. 没有覆盖的

- 真机上的扫码、相机、安装包没有自动验证，要接手机走一遍第 4 项。自动彩排走的是浏览器，核销用手输码。
- 真实微信支付没有联调（`docs/ops/微信支付联调清单.md`）。
