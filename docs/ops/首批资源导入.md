## 2. 填表规则

- 用 Excel 或 WPS 打开模板，**第一行表头不要改**，从第二行起一行一条，另存为“CSV UTF-8”。一张表最多几千行；更多时分几个文件，文件名后面加序号。
- 表之间用你自己起的编号互相引用：经营主体用 `organization_code`（会存进库里，以后也用它），其余用 `product_ref`、`sku_ref`、`activity_ref`、`venue_ref`、`project_ref`、`service_ref`、`article_ref`、`block_ref`、`topic_ref`（只在这次导入里用，导入时换成系统生成的 ID，并把对照表留在导入记录里）。同一个编号在同一类里不能重复。
- 枚举一律填英文编码（表里给了每个可选值），不要填中文说明。
- 金额一律是**整数，单位分**（19.90 元填 1990），不要带小数点和“元”。
- 时间是**北京时间**，`2026-12-06 09:00`；日期 `2026-12-06`。
- 城市用平台城市目录的编码（东营 `370500`），不是城市名。
- 图片、视频只填**受控的 https 地址**；没有授权的图就空着，App 显示灰底，不会显示原型图。
- 个人信息：表里只有机构信息。操作员只要登录名和显示名，**不收手机号、身份证号，不写密码**；场馆电话只填对外咨询电话。
- 状态先填草稿（`DRAFT` / `UNPUBLISHED` / `DISABLED`），核对完再统一改成上架，避免没审完的东西出现在 App 里。

## 3. 每张表

导入顺序就是编号顺序：后面的表引用前面的编号。“对应字段”是导入工具要写的表和列；括号里的是不进库、只用来核对或引用的列。`id`、`version`、`created_at`、`updated_at`、`sample`（示例标记，正式数据一律 false）和计数类字段（已报名人数、已预约人数、完成次数）由系统生成，不在模板里。

## 4. 导入工具

2026-11-23 起在运营端（`apps/admin`）“批量导入”页，契约 `contracts/openapi-ops-import.yaml` 1.0.0，只给平台运营：

- 选一类、选这一类的几张 CSV（文件名就是模板名，后面可以加 `-序号`），点“预检”：逐行列出问题（文件、行、列、为什么），不进库的核对列（统一社会信用代码、`business_roles`）单独列出来给你和线下材料对照，不存。全部通过才能点“导入”。
- 导入在一个事务里写，失败不留半截；写之前按库里当前数据再校验一次。同一批次再点一次、或者同样内容的文件再传一次，都不会重复写（批次标成“已导入”并指向第一次）。各 `*_ref` 编号记在对照表里，下次导入同一编号是更新。供给没有自己的编号，按“规格编号 + 商家编码 + 城市”认。
- 能写入的：经营主体与操作员（新账号的一次性初始口令只在导入结果里显示一次）、收款账户、商品与供给（带了参数表 / 包装清单就整份替换这一批里每个商品的参数 / 包装清单，没带就不动；商品的卖点按 `selling_points` 整份替换）。活动与场次、场馆与项目、巡检和专业服务、发现内容这一版只做预检，导入会提示“只能预检”。
- 内容表（07d、07f）里引用活动、场馆、巡检和专业服务的编号，这一版只查格式（那几类还不能导入，对照表里没有）；引用商品的编号要先导入商品，或直接填库里的 ID。
- 导入文件存私有存储，保留 180 天（开发环境存本机目录；其他环境要先接对象存储，没接时预检返回“存储暂不可用”）。到期清理还没有做定时任务。

下面是当初定的要求，上面都按它做了：

S3 的 Web 运营端（`apps/admin`，Vue 3 + TS + Vite + Element Plus）里做“批量导入”一页，服务端在各模块加平台运营（`PLATFORM_OPERATOR`）才能调的导入接口，模块之间不直接写对方的表。要求：

1. **先校验、后写入**：上传一组 CSV 后先整体校验，逐行报出错误（第几张表第几行哪一列、为什么），全部通过才允许写入；校验规则就是上面每张表的“怎么填”和数据库约束（枚举、长度、金额非负、场次时间先后、收费活动必须有价格等），外加跨表引用（编号找不到、商家没登记收款账户却上架了标价商品）。
2. **一组 CSV 在一个事务里写入**（或按模块分批，每批一个事务），失败不留半截数据。
3. **幂等**：每次导入有批次号；同一批次重复提交不重复建数据。按 `organization_code` 和各 `*_ref` 记一张对照表（批次、编号、生成的 ID），第二次导入同一编号时是“更新”，不是“新建”。
4. **审计**：记录谁在什么时候导入了哪一批、改了哪些对象；导入文件本身存进私有桶，保留 180 天。
5. **不进库的列**（统一社会信用代码、`business_roles`）只在校验页显示，用来和线下材料核对。
6. 操作员账号导入后不设密码，由平台给每个账号发一次性初始密码（或等 S5-8 手机号登录做好后改为短信登录）。
7. 导入后默认都是草稿或停用状态，运营在列表里逐条核对后上架。

在运营端做好之前的过渡做法：你把填好的 CSV 发到约定的受控位置（不要用聊天发），我们写一次性 SQL（按上面的规则校验、生成 ID、一个事务写入），先在一份恢复出来的库上试导（`infra/prod/backup/pg-restore.sh --into`），核对后再导正式库；导入前做一次备份。
