# 巡检预约原生地图选点设计

## 目标

在 INS-M-004 预约填写页中，把“巡检地点”从自由文本输入改为原生地图选点。用户选择后，移动端同时保存完整地址、经度和纬度，并随预约创建请求写入现有 PostgreSQL/PostGIS 数据模型。

## 用户流程

```text
点击“巡检地点”
→ 系统请求定位权限并打开 uni.chooseLocation
→ 用户搜索或在地图上选择地点
→ 移动端接收地点名、详细地址、经纬度
→ 预约页展示完整地址
→ 用户提交预约
→ POST /api/v1/inspection/reservations
→ 后端持久化地址和 PostGIS 坐标
→ 进入预约提交结果页
```

用户取消选点时保留原值，不显示错误。权限拒绝、地图服务不可用或返回无效地点时，不修改草稿，显示可重试的明确提示。

## 范围

- 使用 `uni.chooseLocation`，不新增自定义地图页。
- 地址展示由“详细地址 + 地点名”去重组合，最长 240 个字符。
- 经度、纬度必须成对存在且在合法范围内。
- 扩展移动端预约 DTO，使其与现有 OpenAPI 的 `InspectionLocation` 一致。
- 声明 App 的 Maps、Geolocation 模块和 Android 定位权限。
- 更新 `docs/flow-map.md`。

## 不做

- 常用地址簿、默认地址、联系人、地址标签。
- 自建 POI 搜索、逆地理编码或地图服务代理。
- 在仓库中保存地图服务 Key。
- 修改后端接口、数据库结构或其他页面。

## 稳定性边界

原生选点比自建地图页代码更少，但正式包仍必须使用与包名、签名匹配的合规地图服务 Key，并确保地点搜索配额可用。标准调试基座可用于开发验证，不能替代正式包配置验收。地图外部配置缺失时，页面必须提示失败，不得生成假地址或只保存坐标。
