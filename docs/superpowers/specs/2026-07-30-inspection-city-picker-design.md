# 巡检服务全国城市选择器设计规格

## 1. 目标

将巡检服务目录页当前仅开发环境可用的三城市 ActionSheet，替换为正式可用的全国城市选择底部弹层。视觉结构参考用户提供的城市选择截图，并支持：

- 搜索城市。
- 展示当前定位城市并允许重新定位。
- 展示最近使用城市。
- 按搜索选择次数展示热门城市。
- 按省份展开全国地级城市树。
- 选择后同步共享当前城市并刷新巡检服务列表。

本任务不修改首页、天气、详情页、预约、订单或支付逻辑。

## 2. 工作区隔离

- 独立分支：`codex/inspection-city-picker`。
- 独立工作树：`.worktrees/inspection-city-picker`。
- 基线：`codex/inspection-integration` 当前已提交版本。
- 不在 `.worktrees/inspection-integration` 写入任何文件。
- 后续集成时只合入本任务的独立提交；若共享安全配置或城市状态存在新改动，再单独解决冲突，不覆盖其他任务。

## 3. 页面结构与视觉

城市选择器保持在巡检目录页内，不新增路由。

底部弹层从上到下为：

1. 半透明遮罩。
2. 顶部圆角弹层、拖动提示条、居中标题“选择服务城市”和关闭按钮。
3. 搜索框，提示语“搜索城市”。
4. 当前定位：
   - 当前城市名称。
   - “当前定位”说明。
   - “重新定位”操作。
   - 当前已选城市显示橙色选中标识。
5. 最近使用：
   - 本机最多保存 3 个。
   - 最近选择的城市排在最前。
   - 无记录时整体隐藏。
6. 热门城市：
   - 显示搜索选择次数最高的 6 个城市。
   - 三列网格。
7. 更多城市：
   - 省级行政区按拼音首字母、完整拼音排序。
   - 点击省份行展开或收起下属地级城市。
   - 同一时间只展开一个省份。
   - 省内城市按拼音首字母、完整拼音排序。
   - 不展示区县层级。
8. 底部安全区说明“选择后自动筛选该城市服务”。

弹层高度不写死为参考图像素；适配 375、390、430 CSS 逻辑像素宽度以及 Android/iOS 底部安全区。

## 4. 交互

### 4.1 打开与关闭

- 点击目录排序条中的城市触发器打开弹层。
- 点击关闭按钮或遮罩关闭。
- 关闭不修改当前查询。

### 4.2 搜索

- 搜索在已加载的全国城市目录中即时过滤。
- 支持城市中文名、完整拼音和拼音首字母匹配。
- 搜索结果按拼音排序。
- 无结果显示“未找到相关城市”。

### 4.3 城市选择

- 从当前定位、最近使用、热门城市、搜索结果或省市树选择城市时：
  1. 更新共享 `currentCity`。
  2. 将城市写入本机最近使用列表。
  3. 关闭弹层。
  4. 目录页重置为第 1 页。
  5. 取消或忽略旧城市请求。
  6. 使用新 `cityCode` 重新查询服务。
- 当前城市没有服务时显示既有空状态，不回退到其他城市，也不伪造服务。

### 4.4 热度计数

- 只有用户在搜索结果中选中城市时，才记录一次搜索选择。
- 仅输入、清空、关闭弹层，以及从热门/最近/省市树选择均不计数。
- 计数写入失败不阻断城市切换；前端不伪造成功热度。
- 服务端采用原子自增，避免并发丢失。

### 4.5 重新定位

- 通过共享定位适配器调用原生定位能力。
- 不使用原生返回的电话区号作为六位城市编码。
- 以定位返回的规范城市名匹配城市目录，得到稳定 `cityCode`。
- 定位失败或匹配失败时保留原城市，并展示明确提示。
- 不依赖天气接口完成城市选择。

## 5. 数据设计

新增正式迁移表 `platform_city`：

| 字段 | 说明 |
| --- | --- |
| `city_code` | 稳定城市编码，主键 |
| `city_name` | 城市名称 |
| `city_pinyin` | 城市完整拼音 |
| `city_initials` | 城市拼音首字母 |
| `province_code` | 省级编码 |
| `province_name` | 省级名称 |
| `province_pinyin` | 省级完整拼音 |
| `province_initials` | 省级拼音首字母 |
| `search_count` | 搜索并选中的累计次数，默认 0 |
| `status` | `ACTIVE` / `INACTIVE` |
| `version` | 并发版本 |
| `created_at` / `updated_at` | 审计时间 |

数据规则：

- 正式数据包含全国省级行政区及其地级行政区的真实名称和稳定编码。
- 正式迁移中的 `search_count` 一律为 0。
- 开发种子脚本为济南、青岛、东营、烟台、潍坊、临沂等城市写入不同的模拟搜索次数。
- 开发种子脚本不会被生产环境加载。
- 热门城市按 `search_count DESC, city_pinyin ASC, city_code ASC` 取前 6 个。

## 6. API

### `GET /api/v1/platform/cities`

公开只读接口，返回：

- `hotCities`：热门城市前 6 个。
- `provinces`：已排序省份数组，每个省份包含已排序城市数组。

返回字段只包含稳定编码、名称和搜索所需拼音，不暴露内部审计字段。

### `POST /api/v1/platform/cities/{cityCode}/search-selections`

公开计数接口：

- 城市必须存在且状态有效。
- 对 `search_count` 原子加 1。
- 成功返回 `204 No Content`。
- 不记录用户标识、精确坐标、搜索原文或其他个人信息。
- 接入现有请求限流能力；本任务不新增第二套限流框架。

OpenAPI 契约单独描述以上接口，不改变巡检服务详情或预约契约。

## 7. 前端边界

新增公共城市能力文件：

- 城市目录领域类型与排序/搜索函数。
- 城市目录 HTTP 适配器。
- `CitySelectionSheet` 组件。
- 最近城市本地存储适配器。
- 定位适配接口。

巡检目录页只负责：

- 控制弹层开关。
- 接收已选择城市。
- 更新共享城市状态。
- 重置分页并重新加载目录。

不修改天气状态，不把城市树数据放入 Pinia，不把城市对象序列化进 URL。

## 8. 状态与错误

- 城市目录加载中：显示轻量骨架。
- 加载失败：显示错误说明和“重新加载”。
- 空搜索结果：显示明确空状态。
- 定位失败：Toast 提示并保留原城市。
- 热度上报失败：静默保留城市切换结果，可记录不含个人信息的错误事件。
- 快速连续切城：只有最后一次服务请求能够更新列表。

- 空库迁移成功。
- 全国城市目录可查询且编码唯一。
- 生产数据热度初始为 0。
